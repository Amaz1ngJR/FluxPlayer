# FluxPlayer 蓝紫赛博朋克 UI 方案

## 1. 视觉定位

设计主题：**Neon Drive Console**。

FluxPlayer 的图标像一个发光的播放核心嵌入机械外壳：深黑蓝金属面板、青蓝与紫粉双色霓虹、切角边框、微型刻线和扫描光。播放器 UI 应该延续这种感觉，让整个应用像一台未来媒体终端，而不是普通窗口上的按钮集合。

目标气质：

- 科技感强，但不牺牲视频观看体验。
- 控件像机械面板上的发光模块，边框有结构，信息有层级。
- 蓝色负责主要操作和可读性，紫色负责状态强调、边缘能量和次级操作。
- 发光只在边缘和交互状态出现，避免整屏过曝。

## 2. 从图标提炼的视觉规则

| 图标特征 | UI 转译 |
| --- | --- |
| 圆角方形机甲外壳 | 播放器底部 Dock、设置面板、首页主面板使用低圆角加切角外框 |
| 中央播放三角核心 | 首页主视觉、播放/暂停按钮、空状态符号统一使用几何发光三角 |
| 左蓝右紫双色光 | 主进度条、顶部/底部光带使用蓝到紫水平渐变 |
| 微型刻线与侧边散热槽 | Dock 两侧、面板标题栏、滑块轨道加入短刻线 |
| 深色金属底 | 全局底色为近黑蓝，面板为半透明蓝黑 |
| 发光边缘 | 只用于焦点、悬停、播放进度头、录制状态、下载状态 |

## 3. 信息架构

FluxPlayer 有三个主要界面状态：

1. **启动/打开媒体页**
   - 打开本地文件
   - 输入网络 URL
   - 只呈现以上两种入口，显示应用身份与媒体终端感

2. **打开中/首帧等待页**
   - 用户提交 URL 后立即呈现播放器外壳
   - 显示解析来源、打开媒体流、缓冲首帧的阶段反馈
   - 在第一帧就绪前保持可见，不让用户面对空白窗口

3. **播放页**
   - 视频画面为第一层
   - 底部控制 Dock 为主操作层
   - 顶部极细状态轨为辅助层
   - 右侧弹出 HUD 面板显示媒体信息、统计、设置、画质、下载
   - 字幕独立于 UI 自动隐藏逻辑

## 4. 首页设计

首页不参考当前实现布局，而做精简的“媒体来源选择终端”。页面中只有打开本地文件与输入 URL 两种交互入口。

布局：

- 全屏深黑蓝背景加入透视网格、扫描纹理、边缘数据轨与蓝紫空间辉光。
- 顶部标题 `FLUX // PLAYER` 使用等宽科技字体与轻微双色错位发光，建立启动仪表台的气势。
- 中央为非交互的能量核心/源矩阵装饰：六边结构、环形刻线与脉冲波形只承担品牌主视觉，不作为第三入口。
- 底部左右各一块切角发光来源卡片：左为本地文件，右为网络 URL；两条路径同时可见并保持同等权重。
- 本地文件卡片的主操作为 `OPEN LOCAL FILE`，采用 cyan 外发光和文件夹符号。
- URL 卡片内是深色“数据插槽”和完整动作按钮 `OPEN URL`，使用 violet/magenta 激活色。
- 不展示拖放、最近打开或其他第三入口，保持选择路径清晰。

推荐结构：

```text
                FLUX // PLAYER
            CHOOSE YOUR MEDIA SOURCE
                 (ENERGY CORE)

┌── 01 / LOCAL FILE ───────┐  ┌── 02 / NETWORK URL ─────┐
│ [   OPEN LOCAL FILE   ]  │  │ [ https:// ... ][OPEN URL]│
└──────────────────────────┘  └───────────────────────────┘
```

## 5. 打开中状态

URL 打开会经历网页流提取、媒体连接以及首帧缓冲，期间用户必须始终看到播放器在工作。提交 URL 后应直接切入 `mockup_opening.svg` 的全窗口播放器外壳，而不是关闭主页后等待播放窗口出现。

### 5.1 状态阶段

| 阶段 | UI 文案 | 对应运行阶段 |
| --- | --- | --- |
| 解析来源 | `RESOLVE SOURCE` | 网页视频提取 / `PlayerState::EXTRACTING` |
| 打开媒体流 | `OPEN MEDIA STREAM` | demuxer、DASH 管道与解码初始化 / `PlayerState::OPENING` |
| 等待首帧 | `BUFFER FIRST FRAME` | 播放已启动但首帧或预缓冲尚未完成 |
| 失败 | `UNABLE TO OPEN STREAM` | 提取、连接或解码初始化失败；提供返回入口 |

### 5.2 可见性规则

- 加载态从 URL 提交当帧出现，并持续到画面首帧已就绪；不能仅依赖 `Controller`，因为当前它在 `Player::open()` 完成后才创建。
- 保留顶部来源状态轨与底部禁用 Dock，使窗口从打开中到播放态没有结构跳变。
- 中央状态面板显示阶段、活动指示器、已等待秒数和截断后的 URL，不伪造可测量的网络百分比。
- 阶段轨可以用确定性步骤状态加循环扫描条；只有真实缓冲量可用时才显示量化百分比。
- 控制条在首帧前置灰；失败时中央面板替换为错误信息和返回首页操作。

## 6. 播放页设计

播放页的 UI 应该像贴在视频画面边缘的 HUD。

### 6.1 底部控制 Dock

当前底部浮层高度 64px，可以升级到 78-86px。高度增加后信息层级更清晰，也更接近图标的厚重机械底座。

结构：

- Dock 背景：`rgba(4, 8, 20, 0.78)`，顶部加模糊感深色遮罩。
- 顶部 2px 主光带：从 cyan 到 violet。
- 上半行：进度轨道 + 时间码。
- 下半行：左侧下载/画质状态，中间播放控制，右侧速度/设置/音量。
- Dock 左右两端加入“散热槽”短线装饰，呼应图标边缘。

进度条：

- 背景轨道为内凹暗蓝。
- 已播放部分为蓝到紫渐变。
- 播放头使用小型发光核心，悬停时变为垂直扫描线。
- 缓冲/下载进度可用细线叠在轨道上方，不抢主进度。

### 6.2 播放按钮组

按钮应该少文字、多图标。

- 播放/暂停：中心主按钮，宽 72-86px，高 30-34px，蓝色主光。
- 停止：小方形紫色按钮。
- 录制视频/录音：默认低亮描边；录制中变红粉色脉冲，文字简化为 `REC V` / `REC A`。
- 速度、画质：小型 segment/chip，显示 `1.0x`、`1080P`。
- 设置、音量：图标按钮；音量 hover 展开水平滑轨。
- 下载进行中：`DOWNLOAD` 旁显示进度条/百分比、暂停与取消按钮，并以紧凑双行显示下载速度与文件大小、`ETA` 预计剩余时间。

### 6.3 顶部状态轨

默认可以非常克制，只在需要时显示：

- 左侧：当前文件名/网页平台。
- 中间：播放状态微弱扫描线。
- 右侧：解码器、硬件加速、字幕、循环等状态芯片。

高度 28-36px，透明度低于底部 Dock。用户鼠标移动时出现，静止后隐藏。

### 6.4 右侧 HUD 面板

媒体信息、统计、设置、下载详情建议统一为右侧 HUD 面板样式：

- 宽 300-360px。
- 背景半透明深蓝黑。
- 标题栏左侧有短横线和标签，如 `MEDIA INFO`、`STATS`。
- 每行信息采用键值布局，键为灰蓝，值为近白/青色。
- 重要状态使用紫色或红粉色。
- 面板外框使用切角线段，不使用厚重圆角卡片。

### 6.5 已有功能入口保留

换肤不能缩减现有操作能力。播放页设计必须显式容纳以下入口：

| 已有能力 | 新 UI 入口 | 说明 |
| --- | --- | --- |
| 播放/暂停、停止、进度跳转 | Dock 中心与第一行进度轨 | 仍为最高频操作 |
| 音量与静音 | Dock 右侧扬声器 + 展开滑轨 | 保持 hover 展开 |
| 录像 | `REC V` 独立按钮 | 激活后展示录制时间/大小 |
| 录音 | `REC A` 独立按钮 | 不能与录像合并为一个 `REC` |
| 速度 | `1.0x` chip | 窄屏移入设置面板 |
| 网页画质、下载 | `1080P` chip 与 `DOWNLOAD` active module | 仅网页视频显示；保留百分比、暂停/取消、速度、文件大小及 ETA |
| 设置 | 明确 `SET` / 齿轮入口 | 提供循环、字幕、面板显示等选项 |
| 媒体信息与统计 | 设置开关、`I` / `S` 快捷键 | 使用右侧 HUD 面板 |
| 截图 | 设置提示区展示 `P SCREENSHOT` | 当前由快捷键触发 |
| 全屏、退出 | 设置提示区展示 `F FULLSCREEN` / `ESC EXIT` | 保持键盘入口可发现 |
| UI 显隐 | 设置提示区展示 `H HUD` | 保留自动隐藏行为 |

## 7. 组件风格

### 7.1 颜色角色

- 主操作：cyan / electric blue
- 次级强调：violet / magenta
- 危险/录制：hot rose
- 背景：near black blue
- 文本：ice white
- 弱文本：steel blue gray

### 7.2 圆角与切角

图标是圆角方形，但内部线条更硬朗。UI 推荐：

- 大面板圆角：6px，叠加 10-16px 切角线。
- 小按钮圆角：3px。
- 进度条圆角：2px。
- 弹窗圆角：4px。

### 7.3 发光层级

发光不是阴影泛滥，而是分层：

1. Base line：1px 实线边。
2. Inner glow：同色 20-35% alpha 内部描边。
3. Outer glow：同色 8-18% alpha 扩散 4-10px。
4. Active pulse：只给播放头、录制、下载中状态使用。

### 7.4 字体

- 标题/时间码/状态数字：`ShareTechMono-Regular.ttf`。
- 普通 UI 文本：ImGui 默认字体或系统 CJK 字体。
- 字幕：保持当前 CJK 自动探测逻辑，字幕颜色不应赛博化过度，优先可读。

推荐字号：

- 首页标题：36-42px。
- Dock 时间码：13-14px。
- 按钮文字：12-13px。
- 面板标题：13px uppercase。
- 面板正文：12-13px。

## 8. 状态设计

| 状态 | 表现 |
| --- | --- |
| Idle | 深色面板 + 低亮蓝边 |
| Hover | 边框亮度增加，出现轻微外发光 |
| Active | 背景加入 12-18% cyan/violet 填充 |
| Disabled | 降低到 28-38% alpha，不发光 |
| Opening | 全窗口播放器外壳 + 中央阶段面板 + 循环扫描条，持续到首帧就绪 |
| Playing | 主进度头轻微脉冲，Dock 顶部光带流动 |
| Paused | 进度头停止脉冲，播放按钮蓝色常亮 |
| Recording | 红粉色点状脉冲 + `REC` 时间码 |
| Downloading | 下载按钮右侧显示小进度槽与速度/ETA |
| Error | 使用 hot rose，不使用大面积红背景 |

## 9. 动效原则

当前项目基于 ImGui，动效应选择低成本绘制：

- 扫描线：使用 `ImGui::GetTime()` 驱动 y/x 偏移。
- 脉冲：用 `sin(t * speed)` 控制 alpha。
- 悬停：直接改变颜色和外框层数。
- 菜单展开：如果不做真实插值，也至少改变位置与透明度层级。
- 自动隐藏：保留现有 3 秒逻辑，但隐藏时 Dock 可先降到 0.18 alpha，再完全消失。

## 10. 可落地优先级

第一阶段，低风险换肤：

- 抽出统一 `CyberpunkTheme` 常量。
- 重写 `setupStyle()` 与 `Controller::init()` 的 ImGui 颜色。
- 增加 DrawList helper：切角框、发光线、机械刻线、图标按钮。
- 替换首页主面板与底部 Dock。

第二阶段，交互升级：

- 底部 Dock 改成两层控制区。
- 右侧 HUD 面板统一样式。
- 速度、画质、设置菜单统一为 HUD popup。
- 下载中状态组件化。

第三阶段，细节增强：

- 顶部状态轨。
- 播放头与录制状态脉冲。
- 小型扫描线与电路刻线。
- 响应式布局，在窄窗口下压缩按钮文字。

## 11. 设计边界

避免：

- 大面积紫蓝渐变背景铺满控件。
- 所有元素都发光，导致信息没有主次。
- 圆角过大，失去图标里的机械感。
- 用装饰遮挡视频画面。
- 首页做成营销落地页。

保留：

- 视频画面完整。
- 控制条自动隐藏。
- 字幕可读性。
- 当前的网页视频、画质、下载、录制能力。
- 独立的录像与录音入口、设置入口，以及媒体信息/统计/截图快捷操作。
