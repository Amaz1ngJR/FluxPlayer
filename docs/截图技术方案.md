# FluxPlayer 截图功能技术方案

---

## 一、当前实现分析

### 1.1 功能概述

当前 FluxPlayer 支持在播放过程中截取视频帧并保存为图片文件，支持 PNG 和 JPEG 两种格式。

### 1.2 架构设计

#### 触发方式
- **键盘快捷键**: 按下 `P` 键触发截图 (`Player.cpp:1243-1255`)
- **UI设置**: 通过设置界面配置截图目录和格式 (`Controller.cpp:1849-1903`)

#### 核心组件

**Screenshot 工具类** (`utils/Screenshot.h/cpp`)
```cpp
class Screenshot {
public:
    static std::string saveFrame(const Frame* frame,
                                  const std::string& outputDir,
                                  const std::string& format = "png");
private:
    static std::string generateFilename(const std::string& ext);
};
```

**配置管理** (`utils/Config.h`)
```cpp
struct Settings {
    std::string screenshotDir;       // 截图保存目录
    std::string screenshotFormat;    // "png" 或 "jpg"
};
```

### 1.3 技术实现流程

#### 帧获取
```cpp
Frame leased;
if (queueManager_->videoFrameQueue()->peekLastRef(leased)) {
    Screenshot::saveFrame(&leased, cfg.screenshotDir, cfg.screenshotFormat);
}
```
- 使用 `FrameQueue::peekLastRef()` 获取 keep-last 保留的最后渲染帧
- 独立引用，不阻塞渲染线程，不受并发 flush 影响

#### 编码流程 (`Screenshot.cpp:46-158`)

1. **色彩空间转换** (使用 `SwsContext`)
   - **PNG**: YUV420P → RGB24 (无损，无色彩空间限制)
   - **JPEG**: YUV420P → YUVJ420P (保留 YUV 域，减少转换损失)

2. **FFmpeg 编码**
   - **PNG 编码器**: `AV_CODEC_ID_PNG`，RGB24 输入
   - **JPEG 编码器**: `AV_CODEC_ID_MJPEG`，YUVJ420P 输入
   - **JPEG 质量控制**: `qmin=1, qmax=3` (高质量)

3. **文件保存**
   - **文件名格式**: `FluxPlayer_YYYYMMDD_HHMMSS_mmm.{png|jpg}`
   - **示例**: `FluxPlayer_20260624_143052_123.png`
   - **目录自动创建**: `std::filesystem::create_directories()`

### 1.4 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `screenshotDir` | `{appDir}/Screenshot` | Windows: `%LOCALAPPDATA%\FluxPlayer\Screenshot`<br>macOS: `~/Library/Caches/FluxPlayer/Screenshot`<br>Linux: `~/.cache/FluxPlayer/Screenshot` |
| `screenshotFormat` | `"png"` | 可选值: `"png"` 或 `"jpg"` |

### 1.5 现有限制

1. **格式单一**: 仅支持 PNG/JPEG，无法保存原始 YUV 数据
2. **色彩空间转换开销**: PNG 需要 YUV→RGB 转换，有性能损耗
3. **无图片查看功能**: 播放器本身不能打开图片文件查看
4. **缺少 YUV 保存**: 调试或质量对比场景无法保存原始 YUV

## 二、新功能需求

### 2.1 功能目标

1. **YUV 格式截图**: 支持将视频帧保存为原始 YUV 文件 (NV12, I420)
2. **图片查看**: 播放器能够加载和显示静态图片（JPG, PNG, YUV）
3. **统一体验**: 查看图片时复用现有渲染管线和 UI 控件

### 2.2 使用场景

| 场景 | 格式选择 | 理由 |
|------|----------|------|
| **普通截图** | PNG/JPEG | 通用格式，可直接分享 |
| **质量对比** | YUV (I420) | 无损保存，避免编码损失 |
| **调试分析** | YUV (NV12/I420) | 保留原始像素数据，便于算法调试 |
| **性能测试** | YUV | 零编码开销，最快截图速度 |
| **图片播放** | JPG/PNG/YUV | 查看截图、测试图、参考图 |

## 三、技术方案

### 3.1 YUV 格式截图

#### 3.1.1 支持的 YUV 格式

| 格式 | 色度采样 | 平面布局 | 文件扩展名 | FFmpeg 格式 |
|------|----------|----------|-----------|-------------|
| **I420** | 4:2:0 | Y + U + V (3平面) | `.yuv` `.i420` | `AV_PIX_FMT_YUV420P` |
| **NV12** | 4:2:0 | Y + UV (2平面) | `.nv12` | `AV_PIX_FMT_NV12` |

**选择理由**:
- **I420**: FFmpeg 最常用格式，与现有解码输出一致，无需转换
- **NV12**: 硬件加速友好（GPU 解码输出格式），OpenGL 渲染直接支持

#### 3.1.2 文件格式设计

**YUV 文件结构** (Raw Binary)
```
[Y Plane]  width × height bytes
[U Plane]  (width/2) × (height/2) bytes  (仅 I420)
[V Plane]  (width/2) × (height/2) bytes  (仅 I420)
或
[UV Plane] (width/2) × (height/2) × 2 bytes  (仅 NV12)
```

**元数据存储** (伴随 .txt 文件)
```
FluxPlayer_20260624_143052_123.yuv
FluxPlayer_20260624_143052_123.txt  // 元数据
```

**元数据内容**:
```ini
format=I420
width=1920
height=1080
frameRate=25
timestamp=2026-06-24 14:30:52.123
source=/path/to/video.mp4
```

#### 3.1.3 实现方案

**新增接口** (`Screenshot.h`)
```cpp

    static std::string saveFrame(const Frame* frame,

    // 新增：保存 YUV 文件
    static std::string saveFrameYUV(const Frame* frame,

                                     const std::string& yuvFormat = "i420");

private:
    static std::string generateFilename(const std::string& ext);
    
    // 新增：写入 YUV 元数据
```

**实现逻辑** (`Screenshot.cpp`)
```cpp
std::string Screenshot::saveFrameYUV(const Frame* frame,
                                      const std::string& outputDir,
                                      const std::string& yuvFormat) {
    const AVFrame* avFrame = frame->getAVFrame();
    
    // 1. 格式转换（如需）
    AVPixelFormat targetFmt;
    if (yuvFormat == "nv12") {
        targetFmt = AV_PIX_FMT_NV12;
    } else {  // 默认 i420
        targetFmt = AV_PIX_FMT_YUV420P;
    }
    
    AVFrame* outFrame = avFrame;
    SwsContext* swsCtx = nullptr;
    
    // 如果源格式不匹配，进行转换
    if (avFrame->format != targetFmt) {
        outFrame = av_frame_alloc();
        outFrame->format = targetFmt;
        outFrame->width = avFrame->width;
        outFrame->height = avFrame->height;
        av_frame_get_buffer(outFrame, 0);
        
        swsCtx = sws_getContext(
            avFrame->width, avFrame->height, (AVPixelFormat)avFrame->format,
            avFrame->width, avFrame->height, targetFmt,
            SWS_BILINEAR, nullptr, nullptr, nullptr);
        sws_scale(swsCtx, avFrame->data, avFrame->linesize,
                  0, avFrame->height, outFrame->data, outFrame->linesize);
    }
    
    // 2. 写入 YUV 数据
    std::filesystem::create_directories(outputDir);
    std::string filename = generateFilename(yuvFormat == "nv12" ? "nv12" : "yuv");
    std::string fullPath = outputDir + "/" + filename;
    
    std::ofstream file(fullPath, std::ios::binary);
    
    if (targetFmt == AV_PIX_FMT_YUV420P) {
        // I420: Y, U, V 三个平面
        file.write((char*)outFrame->data[0], outFrame->width * outFrame->height);
        file.write((char*)outFrame->data[1], (outFrame->width / 2) * (outFrame->height / 2));
        file.write((char*)outFrame->data[2], (outFrame->width / 2) * (outFrame->height / 2));
    } else {
        // NV12: Y, UV 两个平面
        file.write((char*)outFrame->data[0], outFrame->width * outFrame->height);
        file.write((char*)outFrame->data[1], outFrame->width * (outFrame->height / 2));
    }
    
    file.close();
    
    // 3. 写入元数据
    writeYUVMetadata(fullPath, outFrame->width, outFrame->height, 
                     yuvFormat, frame->getSourcePath());
    
    // 4. 清理
    if (swsCtx) {
        sws_freeContext(swsCtx);
        av_frame_free(&outFrame);
    }
    
    LOG_INFO("YUV screenshot saved: " + fullPath);
    return fullPath;
}
```

### 3.2 图片查看功能

#### 3.2.1 架构设计

**核心思路**: 图片文件走独立路径，直接解码注入帧队列，不启动 Worker 线程

```
图片文件
  ↓
Player::openImageFile()
  ├─ JPEG/PNG: avformat_open_input + avcodec_receive_frame
  └─ YUV/NV12: 读取裸字节 + 元数据/文件大小猜分辨率
  ↓
AVFrame → videoFrameQueue (size=2, keepLast=true)
  ↓
initWindowAndRenderer() (按图片尺寸建窗口/渲染器)
  ↓
play() (isImageMode_=true, 跳过 Worker 启动)
  ↓
主渲染循环 renderFrame() → keep-last 永久缓存 GPU 纹理
```

**与常规视频的区别**:
- **无 Worker 线程**: 不创建 DemuxWorker / DecodeWorker / AudioOutput
- **单帧注入**: `openImageFile()` 解码完毕后直接 push 到 `videoFrameQueue`
- **keep-last 保持**: 帧队列 `size=2, keepLast=true`，首帧渲染后 GPU 纹理永久缓存，无需重复上传
- **窗口自适应**: `initWindowAndRenderer()` 按图片实际尺寸创建窗口（限制在屏幕 80% 以内）

#### 3.2.2 支持的图片格式

| 格式 | 解码方式 | 分辨率检测 |
|------|----------|-----------|
| **JPEG** | FFmpeg `avformat_open_input` → `avcodec_receive_frame` | 解码帧 `width/height` |
| **PNG** | 同上 | 同上 |
| **YUV (I420)** | 读取裸字节 → `AVFrame` 三平面 (Y+U+V) | ① `.txt` 元数据优先 <br> ② 文件大小匹配常用分辨率 (精确单帧优先) <br> ③ 兜底 1920×1080 |
| **NV12** | 读取裸字节 → `AVFrame` 半平面 (Y+UV) | 同上 |

**格式判定**: 扩展名 `.nv12` → NV12，`.yuv`/`.i420` → I420（业界标准约定，裸字节无法区分）

#### 3.2.3 实现方案

**入口**: `Player::openImageFile()` (src/core/Player.cpp:2015+)

**JPEG/PNG 路径**:
```cpp
AVFormatContext* fmtCtx = nullptr;
avformat_open_input(&fmtCtx, path.c_str(), nullptr, nullptr);
avformat_find_stream_info(fmtCtx, nullptr);

AVCodecContext* codecCtx = /* 查找视频流解码器 */;
AVFrame* imgFrame = av_frame_alloc();
avcodec_receive_frame(codecCtx, imgFrame);  // 解码首帧

// 非 YUV420P/YUVJ420P 需转换
if (imgFrame->format != AV_PIX_FMT_YUV420P) {
    SwsContext* swsCtx = sws_getContext(/* ... */);
    sws_scale(swsCtx, imgFrame->data, /* ... */, yuvFrame->data);
    imgFrame = yuvFrame;
}
```

**YUV/NV12 路径** (无 FFmpeg 容器，纯裸字节):
```cpp
// 1. 读取元数据 (.txt 文件) 或按文件大小猜分辨率
int w = 0, h = 0;
std::ifstream meta(path + ".txt");
if (meta.is_open()) {
    // 解析 width= / height= 行
} else {
    // 按文件大小匹配常用分辨率 (两轮: 精确单帧 → 多帧整数倍)
    // 公式: fileSize × 2 == W × H × 3 (避免浮点)
    // 覆盖 QCIF 到 4K 共 20 种分辨率
}

// 2. 分配 AVFrame
AVFrame* imgFrame = av_frame_alloc();
imgFrame->format = isRawNV12 ? AV_PIX_FMT_NV12 : AV_PIX_FMT_YUV420P;
imgFrame->width = w;
imgFrame->height = h;
av_frame_get_buffer(imgFrame, 0);

// 3. 读取裸字节到 AVFrame 平面
std::ifstream file(path, std::ios::binary);
// I420: 读取 Y(W×H) + U(W/2×H/2) + V(W/2×H/2)
// NV12: 读取 Y(W×H) + UV(W×H/2)
```

**统一后处理** (JPEG/PNG/YUV 汇合):
```cpp
videoWidth_ = imgFrame->width;
videoHeight_ = imgFrame->height;

initWindowAndRenderer();  // 按图片尺寸建窗口

// 注入帧队列 (size=2, keepLast=true)
queueManager_->videoFrameQueue()->start();
Frame* slot = queueManager_->videoFrameQueue()->peekWritable();
slot->setAVFrame(imgFrame, 0.0);  // PTS=0
queueManager_->videoFrameQueue()->push();

isImageMode_ = true;
setState(PlayerState::STOPPED);
```

**播放启动** (`Player::play()` 简化路径):
```cpp
if (isImageMode_) {
    shouldQuit_.store(false);
    clockController_->avSync()->reset();
    setState(PlayerState::PLAYING);
    return true;  // 跳过 Worker 启动
}
// ... 常规视频路径启动 DemuxWorker/DecodeWorker ...
```

**渲染** (`Player::renderVideoFrame()` keep-last 机制):
```cpp
if (queueManager_->videoFrameQueue()->peekRef(leasedFrame)) {
    double nextPTS = leasedFrame.getPTS();  // 0.0
    if (nextPTS <= masterClock + 0.005) {
        renderer_->renderFrame(leasedFrame);  // 首次上传 GPU 纹理
        queueManager_->videoFrameQueue()->consume();  // keep-last 保留槽
    }
}
// 后续帧: renderCachedFrame() 直接复用 GPU 纹理，无 CPU→GPU 拷贝
```

#### 3.2.4 分辨率检测算法 (YUV/NV12)

**三级降级策略**:
1. **`.txt` 元数据** (FluxPlayer 截图自动生成): 精确宽高 + 格式
2. **文件大小匹配**: 按 `fileSize × 2 == W × H × 3` 遍历常用分辨率 (两轮: 精确单帧优先 → 多帧整数倍兜底)
3. **默认兜底**: 1920×1080 + WARN 日志

**匹配表** (覆盖 176×144 到 4096×2160 共 20 种):
```
QCIF, CIF, 640×360, VGA, NTSC D1, PAL D1, SVGA, XGA, 
720p, WXGA, 1280×960, 1280×1080, 1440×1080, 
1080p, 1080p-aligned, 2K, 1440p, 4K UHD, DCI 4K
```

**示例**:
- `1382400 字节 × 2 = 2764800 = 1280 × 720 × 3` → **720p** ✅
- `3110400 字节 × 2 = 6220800 = 1920 × 1080 × 3` → **1080p** ✅

**UI 适配**:
- 进度条禁用 (duration=0)
- 播放/暂停/跳转功能自动隐藏 (图片无时间维度)
- 截图、缩放、信息面板正常工作

## 五、技术风险与应对

### 5.1 YUV 文件兼容性

**风险**: 不同工具对 YUV 文件的解析方式不同（stride 对齐、平面顺序）

**应对**:
- 元数据明确记录格式和尺寸
- 提供 Python 脚本验证 YUV 文件正确性
- 文档说明推荐的第三方查看工具（YUView, FFplay）

### 5.2 内存开销

**风险**: 高分辨率 YUV 文件较大（4K I420 约 12MB）

**应对**:
- YUV 截图仅用于调试场景，日常使用 PNG/JPEG
- 配置默认值仍为 PNG

### 5.3 图片查看性能

**风险**: 大尺寸图片加载可能卡顿

**应对**:
- 复用现有帧队列机制，单帧加载无性能瓶颈
- 大图自动缩放适配窗口

### A.2 YUV 分辨率检测（无元数据兜底）

```cpp
// openImageFile() 内：无 .txt 元数据时按文件大小推断分辨率
// I420/NV12 帧大小均为 W×H×3/2 字节，用 fileSize×2 == W×H×3 避免浮点
static constexpr std::pair<int,int> kCommonRes[] = {
    {176,144},{352,288},{640,360},{640,480},{720,480},{720,576},
    {800,600},{1024,576},{1024,768},{1280,720},{1280,800},{1280,960},
    {1280,1080},{1440,1080},{1920,1080},{1920,1088},{2048,1080},
    {2560,1440},{3840,2160},{4096,2160}
};
auto fileSize = (int64_t)std::filesystem::file_size(path);
// 两轮匹配：pass0 精确单帧，pass1 整数倍多帧（避免小分辨率误命中大文件）
for (int pass = 0; pass < 2 && w <= 0; pass++) {
    for (auto [rw, rh] : kCommonRes) {
        int64_t frameBytes2 = (int64_t)rw * rh * 3;  // = W×H×3/2 × 2
        bool match = (pass == 0) ? (fileSize * 2 == frameBytes2)
                                 : (frameBytes2 > 0 && (fileSize * 2) % frameBytes2 == 0);
        if (match) { w = rw; h = rh; break; }
    }
}
if (w <= 0 || h <= 0) { w = 1920; h = 1080; }  // 最终兜底
```
