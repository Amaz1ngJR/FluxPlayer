# FluxPlayer 播放速度控制

## 1. 速率入口

Controller 的速度菜单调用 `Player::setPlaybackSpeed()`，由 SetSpeed 命令在控制线程应用。`setPlaybackSpeedInternal()` 拒绝非有限值，并将速率限制在 0.5x 到 `HardwareInfo::maxSupportedPlaybackSpeed(width, height)` 返回的上限；候选档位最高为 16x。

播放页按当前视频分辨率裁剪菜单，设置页默认倍速按 1080p 能力裁剪。硬件能力估计不是每个输入都能持续达到所选倍速的保证。

## 2. 主时钟

- 启用音频输出时使用 `AUDIO_CLOCK`，不因高倍速切到外部时钟。
- 无音频播放分支时使用 `EXTERNAL_CLOCK`。
- 视频只根据主时钟等待、显示或丢弃过期帧，不反向推进音频主时钟。

外部时钟按 `offset + elapsed × rate` 计算。变速前先结算旧速率下的位置，再更新基准与速率；暂停中 Seek 更新冻结位置，恢复从该位置继续。

## 3. 音频变速

音频解码器产生 S16。`FrameQueue::renderAudio()` 以采样相位读取输入，按速率推进相位，使用最近邻采样生成输出。相位跨帧和跨设备回调保存，flush 才重置；快放音调升高，慢放音调降低，不做保音调处理。

`Player::audioOutputCallback()` 先将输出缓冲清零，再填入有效采样；不足部分保持静音，不拉伸已有音频。逐输出采样的媒体起止位置写入预分配数组，设备提交成功后由 `AudioOutput` 通知 AVSync 登记覆盖。

音频时钟只在有效覆盖区间内插值。区间保存生成时的媒体跨度，因此新速率不会改变已经排队的 PCM。覆盖耗尽后冻结，欠载静音和回调块大小都不合成媒体进度。

变速不执行内部 Seek，不清空音频队列，也不丢弃设备中的旧速率 PCM。普通暂停保留覆盖，恢复时平移时间锚点；Seek 则在清设备缓存后重建覆盖。

## 4. 视频调度

视频渲染根据帧 PTS 与主时钟的关系选择显示时机。高倍速通过消费过期帧、批量选取到时帧和固定间隔抽帧降低显示负担。本地文件使用硬件解码且速率达到 2x 时启用固定间隔策略；解码完成后的显示丢帧不破坏解码参考关系。

详细策略与能力裁剪见 [高倍数播放](v0.8.0高倍数播放.md)。

## 5. 实现位置与限制

| 位置 | 职责 |
| --- | --- |
| `src/core/Player.cpp` | 命令入口、速率限制、音频填充、视频调度 |
| `src/core/FrameQueue.cpp` | 最近邻采样、相位保存、有效覆盖生成 |
| `src/audio/AudioOutput.cpp` | 平台提交、软件音量、提交成功通知 |
| `src/core/AVSync.cpp` | 覆盖区间音频时钟、外部时钟速率 |
| `src/utils/HardwareInfo.cpp` | 硬件能力与解码测速 |

音频播放时刻依据设备排队延迟估计，不读取精确硬件消费游标。音频回调使用互斥锁，消费路径不执行 FFmpeg 帧引用操作。实际音频吞吐不足时主时钟会冻结，所选倍速不意味着持续达到该倍率。
