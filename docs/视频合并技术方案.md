# FluxPlayer 多视频合并技术方案

## 一、需求概述

- 在主页面提供入口，用户可选择多个本地视频文件，按指定顺序合并为一个视频
- 合并结果输出到录制目录（`Config::recordDir`，与录像/录音共用）
- 支持文件多选、拖放添加、列表内拖拽调序、单项删除
- 合并过程显示进度，可取消；完成后停留在合成界面提示成功路径
- 不引入新的第三方依赖（沿用项目已链接的 FFmpeg libav* 库）

## 三、智能合并策略

合并在 `VideoMerger` 后台线程执行，分三阶段：**探测 → 决策 → 写出**。

### 1. 探测（Probing）

逐个 `avformat_open_input` 打开输入，记录视频/音频编解码参数与时长后立即关闭（不长期持有句柄）。任一文件无有效视频流即判失败。

### 2. 决策

```
所有文件视频参数一致（codec_id / 宽 / 高 / pix_fmt）
  且 音频要么全部缺失、要么全部一致（codec_id / 采样率 / 声道 / 采样格式）
            │
      ┌─────┴─────┐
     是           否
      │           │
   流拷贝      统一转码
  (.mkv)       (.mp4)
```

### 3a. 流拷贝路径（runStreamCopy）

- 输出 Matroska 容器，以首文件参数 `avcodec_parameters_copy` 建立输出流并写文件头
- 逐文件 `av_read_frame` 读包，`av_packet_rescale_ts` 转到输出 time_base
- 各输出流维护累计偏移 `streamOffset`，按**文件时长**统一推进（视频/音频用同一时长换算各自 time_base 刻度），保证文件衔接处 A/V 同步、时间戳单调递增
- 零重编码，速度接近磁盘 IO 上限，画质无损

### 3b. 统一转码路径（runTranscode）

- 输出 MP4：H.264（YUV420P，CRF 23，preset medium）+ AAC（128kbps，FLTP）
- 视频：逐文件解码 → `sws_scale` 缩放到首文件分辨率 → H.264 编码；PTS 用全局帧计数器连续递增，跨文件不回退
- 音频：解码 → `swr_convert` 重采样到统一格式 → 写入 `AVAudioFifo` → 按编码器 `frame_size` 取整帧送 AAC；采样计数 `aNextPts` 跨文件连续
- 音轨规则：所有输入都含音频才输出音轨；任一文件无音频则输出纯视频（避免静音填充复杂度，UI 提示）
- 视频 `time_base` 取首文件帧率倒数，兼容 24000/1001 等分数帧率

### FFmpeg 版本适配

项目 Windows 捆绑 FFmpeg 7.x（新 `ch_layout` API），macOS 捆绑 4.x（旧 `channels`/`channel_layout` API）。所有声道相关代码用 `LIBAVUTIL_VERSION_MAJOR >= 57` / `LIBAVCODEC_VERSION_MAJOR >= 59` 宏分支，与 `AudioDecoder.cpp` 一致。`VideoMerger.cpp` 内 `FLUX_PAR_CHANNELS` 宏统一读取声道数。

## 四、线程模型与取消

- `start()` 在 UI 线程调用，启动后台 `mergeLoop` 线程；UI 线程每帧调 `progress()` / `state()`（原子读取）刷新进度
- 状态用 `std::atomic<State>` 发布；`error_` / `outputPath_` 用 `mutex_` 保护
- 取消：`cancel()` 置原子 `cancelRequested_`，写出循环每轮检查并尽快中止，随后删除半成品文件
- `MergeScreen::destroy()` 离开界面时若仍在运行会请求取消；`VideoMerger` 析构 `join` 线程，保证不泄漏

---

## 五、输出与配置

- 输出目录复用 `Config::recordDir`，**不新增配置项**
- 文件名 `FluxPlayer_Merge_<YYYYMMDD_HHMMSS>.<ext>`；扩展名由策略决定（流拷贝 `.mkv` / 转码 `.mp4`），`VideoMerger` 在决策后校正
