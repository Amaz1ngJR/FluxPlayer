# 本地实时字幕

播放器将已解码、尚未变速和音量缩放的音频送入独立识别线程，经 FFmpeg 重采样为 16 kHz 单声道 float PCM，再由 whisper.cpp 生成字幕。不读取麦克风，不上传音频，不需要 API Key。

## 使用

1. 构建包含 Whisper 的播放器，准备多语言 `ggml-*.bin` 模型。
2. 打开设置的 SUBTITLES 分组，启用 **AI Subtitles**；**Whisper Model** 留空即使用内置 base Q8，或选择自行下载的模型文件。
3. **Speech Language** 填 `zh`、`en`、`ja` 或 `auto`；**AI GPU Acceleration** 控制是否使用编译时启用的 GPU 后端。
4. 重新打开媒体。以上识别设置在打开媒体时读取；字幕总开关仍控制是否显示字幕。

AI 开启后优先显示识别结果，替代内嵌字幕；关闭 AI 后重新打开媒体即可恢复内嵌字幕。模型加载和错误信息显示在字幕区域。模型未配置、无法读取或当前构建不包含 Whisper 时，会明确提示，不影响音视频播放。

字幕层使用专用 CJK 字体，加载完整基本汉字范围，避免繁体和非常用字因常用简体字集限制显示成 `?`。自定义字幕字体可在 SUBTITLES 中选择，重启播放器生效；字体文件本身也需包含相应中文字形。

Font Scale 调整会立即传入 Lua 字幕层，默认皮肤同步缩放文字和背景，无需重新打开媒体。自定义皮肤可通过字幕数据的 `fontScale` 字段获取当前倍率。

仅内置 `source/models/whisper/ggml-base-q8_0.bin`（约 77.98 MiB），替代约 141 MiB 的原版 base。构建及安装时通过白名单部署 base Q8 和说明文档，与超分模型的资源管理方式一致；运行时从程序资源目录定位，不依赖开发机的绝对路径。原 `models/whisper` 已迁移。

small 不随项目或安装包内置。可[下载多语言 ggml-small.bin](https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin)（约 466 MiB），然后在 **Whisper Model** 中选择下载的文件。设置中也提供此下载链接提示。

设置说明会在控件下方换行显示。Lua 界面的展示文字可右键打开选择/复制面板，拖选后用 Ctrl+C / Cmd+C 复制，或点击 Copy all；含链接的说明另有 Copy link 按钮，可复制原始链接。输入框支持原有的直接选择和复制。

配置示例（写入实际配置文件的 `[Subtitle]` 段；实际路径可在程序日志中查看）：

```ini
subtitleEnabled=true
aiSubtitlesEnabled=true
aiSubtitleModel=
aiSubtitleLanguage=zh
aiSubtitleGpu=true
```

## 构建

CMake 默认使用项目内 `third_party/whisper.cpp`，无需另外下载依赖源码：

```sh
rtk proxy cmake -S . -B build/cmake -DCMAKE_BUILD_TYPE=Release \
  -DFLUX_WHISPER_SOURCE_DIR=/absolute/path/to/FluxPlayer/third_party/whisper.cpp
rtk proxy cmake --build build/cmake --target FluxPlayer -j 4
```

依赖版本为 `aba02defd6bb6ff5de63721c21e3456645c153e2`，也是本次验证版本。CMake 将 Whisper 和 GGML 静态链接到播放器，不需要部署 Whisper 动态库。当前裁剪版保留 CPU、BLAS、Metal 后端，macOS 默认使用 Metal；未保留 CUDA/Vulkan 等其他加速后端。显式传入 `-DFLUX_WHISPER_SOURCE_DIR=` 可构建基础播放器，启用 AI 会提示构建缺少识别能力。

base 已内置，无需下载或手动选择。更换模型时使用 whisper.cpp 兼容的 ggml 模型；中文需要多语言模型，不能使用仅英语的 `.en` 模型。程序不自动下载模型，裁剪版也不保留上游模型下载工具。

xmake 同样默认启用 AI 字幕，自动用 CMake 构建并静态链接项目内 Whisper，不需要单独准备共享库。旧配置中空的 `whisper_root` 表示使用项目内源码。可用 `xmake f --ai_subtitles=n` 显式关闭；`--whisper_root=/absolute/path/to/whisper.cpp` 可覆盖源码路径。依赖构建产物位于 `build/whisper/<平台>/<架构>/<模式>/`。Windows/Linux 构建尚未实际验证。

## 行为和限制

- 当前在累积至少 2.5 秒音频后，优先寻找连续 400 毫秒的低能量停顿切分，连续讲话最长 8 秒切一次。识别块不重叠，EOF 提交剩余尾段（少于 0.4 秒跳过）。字幕在对应音频块结束后显示，最长保留到块结束后 6 秒，新结果优先。字幕带数秒延迟，不承诺逐字同步。
- 使用 beam size 5 多候选解码。识别提示和最近一次较高置信度的文本分别最多保留 96 token，显式传入下一次识别，防止未采纳的结果留在引擎内部上下文。平均文本 token 对数概率低于 -0.8 时，去掉前文、用 beam size 8 最多重试一次；仅在输出长度相近且评分更好时采用复识别结果。低评分文本仍可显示，但不作为后续上下文。该评分仅是启发式指标，不能保证文字正确，重试可能增加耗时。
- 设置中的 **Recognition Hints** 可填写简短术语、人名、产品名，例如 `邮箱、登录、内网账号、默认密码`，重新打开媒体后生效。提示最多使用 96 token（含中文风格提示），过长部分不使用。它是给语音识别提供词汇线索，不是盲目替换同音词。Seek、音频间断、格式变化、空结果及静音块后重置近期文本上下文，术语提示保留。
- 使用媒体时间控制显示，暂停不会因墙钟流逝而让字幕过期；倍速不改变字幕时间基准。高倍速可能丢弃待识别音频以保证播放响应。
- 识别队列最多保留 64 个音频帧、最多 8 条结果。过载丢弃旧帧；检测音频间断或格式变化后重置分块与重采样，防止拼接无关音频。
- Seek 通过 packet serial 隔离结果，旧结果不会显示到新位置；识别任务观察代际取消。切媒体、画质切换、循环重启和退出时停止旧识别服务。
- 重采样和推理均在识别线程执行；解码线程只引用计数复制音频帧并提交有限队列，设备回调不执行识别。
- 停顿切分和静音过滤只依据音频能量，不是完整语音 VAD。音乐、噪声仍可能产生幻觉；未加入翻译、语义润色、滚动窗口修订或 SRT 导出。base 模型能力有限；可以在设置中选择更大的多语言模型，但速度和资源占用需另行评估。
- 模型在每次播放会话启动时加载；首次 GPU 初始化可能较慢，加载阶段可能丢弃早期音频。底层模型初始化不支持本服务的推理取消回调，退出若恰逢模型加载会等待初始化返回。

## 验证

完整 macOS Release 播放器已编译，并使用临时程序调用实际识别服务，确认真实语音出字、未来字幕门控、过期清理、Seek 清理、拒绝陈旧输入、新位置恢复识别、EOF 尾段、取消和模型缺失错误。检查使用本地中文语音、base 模型、Metal。按用户要求不在仓库中保留测试源码。

这些是服务级检查，不能代替窗口交互、长时间直播、高倍速负载和识别准确率测试。

### 模型与词汇提示的离线对比（2026-11-16）

同一段 20 秒中文讲解音频，在 Apple M3 上使用 whisper-cli、CPU、4 线程、beam 5、固定 zh、关闭温度重试，并给出简体风格提示：base 全流程日志计时约 2.19 秒，small 约 6.06 秒。small 将 base 的“心同学”识别成“新同学”，但仍把“域名”识别为“预名”；加入 `邮箱、内网账号、域名、登录、新同学` 后该句输出“域名”，耗时约 5.75 秒。公司名依然存在错误，截断到半句的末尾也出现了误识别，因此不能据此声称总体字错率下降了某个百分比。

上述为完整文件的离线转录对比，不是当前流式分段/复识别的端到端耗时，也不包含翻译。使用同一真实视频进行播放验收，仍是选择模型和提示词的依据。当前新增的低置信度重试逻辑已编译，尚未量化其对具体视频字错率的影响。
