# FluxPlayer 状态控制与并发边界

本文描述帧队列、Seek、EOF、录制和时钟的当前线程契约。控制线程与组件关系见 [命令队列与控制线程架构](v0.6.0命令队列与控制线程架构重构方案.md)。

## 1. 帧队列所有权

`FrameQueue` 为固定容量、单生产者/单消费者队列，内部互斥锁保护索引、容量、代际、元素身份及音频相位。

### 生产者

- 转换在私有 `Frame` 上执行，不向生产者暴露可写队列槽指针。
- `outputTag(serial)` 在转换开始前捕获包 serial 和帧队列 epoch。
- `trySubmit(prepared, tag)` 在锁内检查身份及容量，仅 `Committed` 通过交换转移引用。
- 队列满时 `waitForSpace(tag)` 有界等待；生产者再次检查退出和代际，而不是把旧帧重新标成新代际。

### 视频消费者

- `peekRef(out, token)` 在锁内增持独立引用并返回 `ReadToken{epoch, itemId}`。
- `consume(token)` 只推进当前匹配元素；重复或过期凭证不修改队列。
- keep-last 保留最后显示帧，`peekLastRef()` 提供暂停重绘和截图所需的独立引用。
- flush 使旧凭证失效，消费者已持有的引用仍负责其数据生命周期。

### 音频消费者

`renderAudio()` 在锁内校验 S16、声道数、采样率和时间戳，直接复制采样并保存跨回调相位。消费不增持或释放 FFmpeg 引用；旧槽引用由生产者交换后回收。flush 与复制串行，并重置相位。

## 2. 队列代际与 Seek

QueueManager 统一处理 packet/frame 边界。解码器使用实际取得的包 serial，不能以迟到 serial 清空新队列。

Seek 目标与请求代际同锁读写。设备清缓存成功后才发布新目标；I/O 完成、包提交、EOF 和对齐事件均检查当前身份。旧 Seek 返回后不覆盖新目标、时钟或恢复意图。

ClockController 使用原子目标 PTS、精确跳转状态和独立单调纳秒计时。解码线程到达目标后退出精确跳转；控制线程周期处理未对齐轨道的超时，不依赖新包到达，视频先完成不停止音频的计时兜底。音频确认 EOF 且软件 PCM、设备有效覆盖均排空后，剩余视频从确认位置切换外部时钟；未确认 EOF 的定位超时进入错误态，不发布实际对齐成功。再次 Seek 恢复音频主时钟；暂停期间等待消费的 PCM 不触发缺包失败，恢复后重算窗口。音频设备恢复由主线程执行。

## 3. EOF 与线程退出

输入 EOF、解码器 drain 完成和线程退出是不同状态。DemuxWorker 在 EOF 停泊期间仍处理控制请求；DecodeWorker 的完成状态绑定包 serial，新代际可恢复消费。

停止与资源释放遵守以下顺序：发布取消意图，停止音频设备，abort 队列唤醒等待者，join Worker，然后销毁使用中的资源。队列 abort 只改变运行状态并唤醒等待者，不替代线程回收。

## 4. 录制线程归属

控制线程向 RecordingService 投递请求；请求容器由互斥锁保护，UI 查询状态使用原子值。Recorder 的创建、写包和封口由 demux 所有者串行执行，控制线程只在 Worker 已退出后执行回收封口。

Start 捕获输入代际，消费时检查当前输入及起录条件；Stop 只在读包边界处理，不中断正在执行的协议读，封口可能等待 I/O 返回。Seek、重连、切流和退出会封口当前录制并使旧 Start 失效。封口失败保留 Error，不被重复 Stop 改写为成功。

## 5. 时钟一致性

外部时钟的基准、offset、速率和暂停状态在同一互斥锁下取快照。暂停冻结当前位置；暂停中 Seek 更新 offset，恢复保留该位置并重建墙钟基准。

音频时钟保存成功提交 PCM 的有效覆盖区间，按设备排队延迟估算播放时刻，在区间内部插值，区间耗尽后冻结。普通暂停保留覆盖并平移恢复锚点，Seek 清缓存后重建。倍速只改变新生成 PCM 的采样跨度，不重新解释已经提交的音频；欠载静音不生成媒体进度。
