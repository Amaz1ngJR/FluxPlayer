# FluxPlayer 观看历史技术方案

> 版本目标：v0.7.0｜状态：已实现
> 本方案遵循 `docs/AI开发守则.md`，新增模块须满足：最小头文件暴露、双构建同步、中文注释、RAII、文档同步。（本功能始终开启、无配置项，不涉及配置热加载。）

---

## 一、需求概述

为 FluxPlayer 增加"观看历史"能力，覆盖两类媒体来源：

1. **本地视频/音频**：通过文件对话框或拖放打开的本地文件。
2. **网页视频**：通过 URL 输入、经 yt-dlp 提取后播放的网页视频（B 站 / YouTube 等）。

功能点：

- **记录历史**：每次成功打开媒体并开始播放时，写入一条历史记录（去重：同一来源更新而非追加）。
- **查看历史**：在 HomeScreen 主界面以列表形式展示最近观看，点击任意一条可直接重新打开播放。
- **删除单条**：列表中每条记录支持单独删除。
- **清空全部**：一键清空所有历史记录（带二次确认，避免误操作）。
- **LRU 上限**：历史最多保留 **10 条**，采用 LRU（最近最少使用）淘汰策略 —— 新观看置顶，超出 10 条时淘汰队尾（最久未观看）的一条。

非目标（本期不做，留作后续迭代）：

- 不做断点续播（仅记录 `lastPosition` 字段预留，UI 暂不消费）。
- 不做缩略图抓帧（`thumbnail` 字段预留为空，UI 用占位图标）。
- 不做跨设备同步、不做云端存储。

### 修改模块

| 模块 | 修改内容 |
|------|---------|
| `src/main.cpp` | 在 `playMediaShared` / `playMediaCli` 成功打开媒体后写入历史；退出播放时回写 `lastPosition` |

### 设计原则对齐守则

- **单一职责**：`HistoryStore` 只负责"历史记录的持久化与查询"，不碰 UI、不碰播放。UI 交互留在 `HomeScreen`，写入时机留在 `main.cpp`，与现有 `CookieStore`（只管 cookie 文件）保持同构。
- **最小头文件暴露**：头文件仅暴露 `HistoryEntry` 数据结构与静态接口，JSON 解析（`nlohmann/json`）只在 `.cpp` 中 include —— 与 `StreamExtractor.cpp` / `SkinManager.cpp` 一致（项目唯一允许引入 json 的位置是 TU 内部）。
- **不引入新依赖**：复用项目已有的 `nlohmann/json`（`third_party/nlohmann`），存储格式选 JSON，与皮肤系统、cookie 解析技术栈一致。

## 三、数据模型

```cpp
// include/FluxPlayer/utils/HistoryStore.h

/// 媒体来源类型：决定 UI 图标与重播路径处理方式
enum class HistorySourceType {
    LocalFile,   ///< 本地文件（path 为文件系统绝对路径）
    WebVideo,    ///< 网页视频（path 为原始网页 URL，重播时重新走 yt-dlp 提取）
    NetworkUrl   ///< 直链 / RTSP / RTMP 等（path 为可直接喂给 FFmpeg 的 URL）
};

/// 单条观看历史记录
struct HistoryEntry {
    std::string       id;            ///< 稳定唯一键（path 的哈希），用于删除/去重
    std::string       path;          ///< 本地路径或网页/网络 URL（重播的唯一依据）
    std::string       title;         ///< 显示标题（本地=文件名，网页=视频标题）
    HistorySourceType sourceType = HistorySourceType::LocalFile;
    int64_t           lastPlayedAt = 0;   ///< 最近播放的 Unix 时间戳（秒），列表按此降序
    double            duration = 0.0;      ///< 媒体总时长（秒），0 表示未知/直播
    double            lastPosition = 0.0;  ///< 上次退出时的播放位置（秒），预留断点续播
    std::string       uploader;      ///< 网页视频上传者（本地为空）
    std::string       platform;      ///< 网页视频平台名（本地为空）
};
```

### 去重键设计

`id` 取 `path` 的稳定哈希（`std::hash<std::string>` 转十六进制字符串即可，无需密码学强度，仅作主键）。同一文件 / 同一 URL 反复观看时，**更新已有条目的 `lastPlayedAt` / `lastPosition` 并置顶**，不产生重复行。

### LRU 淘汰策略

历史上限固定为 **`kMaxEntries = 10`**（具名常量，定义在 `HistoryStore.cpp`，符合守则五"Magic Number 提取为具名常量"）。LRU 语义由"列表头部=最近、尾部=最久"的有序结构天然承载：

- **命中（已存在）**：更新字段后从原位置移除、重新插到头部 → 等价于 LRU 的"访问即提升"。
- **未命中（新条目）**：插到头部。
- **淘汰**：每次 `record` 写入后，若 `entries.size() > 10`，从队尾连续 `pop_back` 直至 ≤10。因单次只新增一条，正常只淘汰 1 条；多删几条是对历史文件被外部改大的兜底。

排序依据是列表物理顺序（写入即维护），`lastPlayedAt` 仅用于跨进程重启后 `loadAll` 的稳定重排序，二者一致。

## 四、HistoryStore 接口设计

```cpp
// include/FluxPlayer/utils/HistoryStore.h
class HistoryStore {
public:
    /// 历史文件绝对路径：getAppDataDir()/history.json
    static std::string getHistoryFilePath();

    /// 读取全部历史，按 lastPlayedAt 降序返回（最近的在前）
    static std::vector<HistoryEntry> loadAll();

    /**
     * @brief 记录一次观看（upsert + LRU 语义）
     *
     * 若 path 对应条目已存在：更新 title/lastPlayedAt/duration/lastPosition，
     * 并移到列表头部（LRU "最近使用置顶"）；否则插入新条目到头部。
     * 写入后若总数超过 kMaxEntries(10)，淘汰队尾（最久未观看）直至 ≤10。
     * @return 成功返回 true，IO/解析失败时 error 含原因
     */
    static bool record(const HistoryEntry& entry, std::string* error = nullptr);

    /**
     * @brief 仅更新某条目的退出播放位置（轻量写，退出播放时调用）
     * 条目不存在则忽略。
     */
    static bool updatePosition(const std::string& path, double position,
                               std::string* error = nullptr);

    /// 删除单条（按 id）
    static bool remove(const std::string& id, std::string* error = nullptr);

    /// 清空全部历史（写入空数组，保留文件）
    static bool clear(std::string* error = nullptr);

    /// 由 path 计算稳定 id（供 UI 与 record 共用，保证一致）
    static std::string makeId(const std::string& path);

private:
    static bool writeAll(const std::vector<HistoryEntry>& entries, std::string* error);
};
```

### 线程安全（守则四：线程安全约束）

- `record` 多在主线程的播放启动点调用，`loadAll` 在 HomeScreen 主线程渲染前调用，理论上同线程。
- 但为与 `CookieStore` 同构、并防止未来后台线程写入，内部用 **函数内 `static std::mutex`** 串行化所有读写（`loadAll` / `record` / `remove` / `clear` 全程持锁），锁粒度为"一次完整的文件读-改-写"。

### 鲁棒性（守则四：错误处理 + 降级）

- 文件不存在：`loadAll` 返回空 vector，不视为错误。
- JSON 解析失败（文件损坏）：记录 `LOG_WARN`，返回空 vector，并在下次 `record` 时以新内容覆盖（自愈，不阻塞主流程）。
- 写入失败：通过 `error` 出参回传，调用方记录日志，但**绝不因历史写入失败而中断播放**（历史是旁路功能）。
- 所有文件句柄用 RAII（`std::ifstream` / `std::ofstream` 作用域控制），目录用 `std::filesystem::create_directories` 兜底创建。
- **持久化跨重启**：历史只存在于磁盘文件 `getAppDataDir()/history.json`，不依赖任何进程内常驻状态。`record` 在每次播放成功时**立即落盘**（不延迟到退出），`loadAll` 在每次进入 HomeScreen 时**重新读盘**。因此"播放 → 关闭播放器（进程退出）→ 重新打开"后，主界面历史列表必然还原到上次退出时的内容。这是文件持久化的天然结果，无需额外的会话保存/恢复逻辑；唯一的丢失场景是用户手动删除该文件或调用"清空全部"。

## 五、存储格式（JSON）

文件位置：`getAppDataDir()/history.json`（与 `fluxplayer.ini`、`cookies/` 同级，属可重生缓存数据）。

```json
{
  "version": 1,
  "entries": [
    {
      "id": "a1b2c3d4e5f6",
      "path": "https://www.bilibili.com/video/BV1xx411c7mD",
      "title": "【官方】FluxPlayer 演示",
      "sourceType": "WebVideo",
      "lastPlayedAt": 1718700000,
      "duration": 366.5,
      "lastPosition": 120.0,
      "uploader": "Amaz1ng",
      "platform": "BiliBili"
    },
    {
      "id": "f6e5d4c3b2a1",
      "path": "/Users/me/Movies/demo.mp4",
      "title": "demo.mp4",
      "sourceType": "LocalFile",
      "lastPlayedAt": 1718699000,
      "duration": 95.0,
      "lastPosition": 0.0,
      "uploader": "",
      "platform": ""
    }
  ]

```

- 顶层 `version` 字段预留迁移空间（未来字段变更时按版本号兼容旧文件）。
- `sourceType` 序列化为可读字符串（`LocalFile` / `WebVideo` / `NetworkUrl`），便于人工排查。

## 六、写入时机与数据来源

### 6.1 记录历史（在 `main.cpp`）

在 `playMediaShared` 与 `playMediaCli` 中，**`player.play()` 成功之后、进入主循环之前**调用 `HistoryStore::record`。此时已具备：

| 字段 | 来源 |
|------|------|
| `path` | `mediaPath`（HomeScreen 回传的原始路径 / URL，未经 yt-dlp 改写） |
| `sourceType` | 由 `isNetworkPath()` 与 `StreamExtractor::needsExtraction()` 判定：<br>`needsExtraction` 为真 → `WebVideo`；否则 `isNetworkPath` 为真 → `NetworkUrl`；否则 `LocalFile` |
| `title` | 本地：`mediaPath` 的文件名（`std::filesystem::path::filename`）；<br>网页：`player.getLastExtractedInfo().title`（已有 getter，见 `Player.cpp:462` 附近用法） |
| `duration` | `mediaInfo.getDuration()` 或 `player.getDuration()` |
| `uploader`/`platform` | 网页视频取自 `lastExtractedInfo_`（已存在），本地留空 |
| `lastPlayedAt` | 当前 Unix 时间戳（`std::time(nullptr)`） |

> 关键：`path` 必须存网页**原始 URL**（`mediaPath`），不存 yt-dlp 解析出的临时流地址 —— 临时流地址会过期，重播必须重新提取。

### 6.2 回写播放位置（在 `main.cpp`）

`player.run()` 返回后（主循环结束），在 `controller->destroy()` 之前调用：

```cpp
HistoryStore::updatePosition(mediaPath, player.getCurrentTime());
```

把退出时的播放进度写回，为后续断点续播预留数据（本期 UI 不消费）。

## 七、UI 设计（HomeScreen 历史面板）

### 7.1 布局

参考 `source/UI/skins/cyberpunk-neon/mockup_home.svg` 的视觉语言，在主卡片**右侧**新增一个"历史"侧栏面板（与中央 source 卡片并列，赛博霓虹描边风格）：

```
┌─────────────────────────────┐   ┌──────────────────────┐
│                             │   │  [ WATCH HISTORY ]   │
│       FLUX PLAYER           │   │  ──────────────────  │
│   > OPEN LOCAL FILE         │   │ ▶ demo.mp4      [x]  │
│   + MERGE VIDEOS            │   │   95s · local        │
│   [ NETWORK URL ____ ] URL  │   │ ▶ B站演示       [x]  │
│                             │   │   6:06 · BiliBili    │
│                             │   │ ...                  │
│                             │   │  ── CLEAR ALL ──     │
└─────────────────────────────┘   └──────────────────────┘
```

- 面板宽度复用皮肤 metrics（如新增 `home.historyPanelW`，或先用现有尺寸常量近似，避免改 schema）。本期为降低皮肤系统侵入，**优先用 HomeScreen 内局部常量**定义面板尺寸，皮肤 token 化留作后续。
- 每条记录：标题（单行省略）+ 副信息行（时长 · 来源/平台）+ 右侧删除按钮 `[x]`。
- 列表底部："CLEAR ALL" 按钮（accent.secondary 描边，点击弹确认）。
- 历史为空时显示占位文案 "No history yet"。

### 7.2 交互流程

1. **进入 HomeScreen** → `init()` 中调用 `HistoryStore::loadAll()` 缓存到成员 `std::vector<HistoryEntry> history_`（避免每帧读盘）。
2. **点击某条记录** → 置 `selectedFile_ = entry.path; fileSelected_ = true;`，复用现有"选中文件即返回"的逻辑。
   - 若 `sourceType == WebVideo`，与现网页 URL 一致会经 `OpeningScreen` 重新走 yt-dlp 提取（无需特殊处理，`mediaPath` 是原始 URL）。
   - 网页视频是否弹登录询问：本期重播**不再弹登录弹窗**（直接打开，复用已存 cookie），简化交互；如需登录用户可回主输入框重新输入。
3. **点击单条 `[x]`** → 调用 `HistoryStore::remove(entry.id)`，成功后从 `history_` 移除该项（不重新读盘）。
4. **点击 CLEAR ALL** → `ImGui::OpenPopup` 弹确认模态（"确定清空全部观看历史？此操作不可恢复"），确认后 `HistoryStore::clear()` 并清空 `history_`。

### 7.3 守则五：函数长度

历史面板渲染逻辑独立为私有方法 `void renderHistoryPanel();`（在 `renderUI()` 末尾调用），删除确认弹窗逻辑独立为 `void renderClearConfirmPopup();`，避免 `renderUI()` 超 80 行。

## 八、无配置项（始终开启）

观看历史是**始终开启**的内建功能，不提供任何开关或可调参数：

- **不新增 `Config::Settings` 字段**，不动 `Config::load()` / `save()`，不动 `fluxplayer.ini.sample`。
- **上限固定 10 条**，以 `HistoryStore.cpp` 内的具名常量 `kMaxEntries = 10` 承载（守则五：Magic Number 提取为具名常量），LRU 淘汰，无用户可调项。
- `record` 无条件写入，无 `historyEnabled` 判断分支。

> 决策理由：历史记录是轻量旁路功能（写入失败也不阻断播放），保留一个"关闭开关"只会增加配置面与代码分支，却几乎无人使用。固定 10 条上限同时规避了"用户调大后主界面读盘变慢"的隐患。隐私场景下用户可用 UI 的"清空全部"入口随时抹除记录。
