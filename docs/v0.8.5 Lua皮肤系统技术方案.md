## 1. 目标与边界

### 1.1 设计目标

FluxPlayer 把皮肤业务交给 Lua。一个 `<id>.lua` 同时描述视觉 token、布局参数和可执行 Surface，C++ 不读取 `skin.json`，也不定义具体皮肤。

- 在程序运行中编辑 Lua，下一批有效帧立即使用新 UI；
- 切换或重载皮肤不停止播放、不重置进度和设置；
- Lua 不接触 ImGui、文件系统、网络或应用核心对象；
- C++ 只提供通用 UI、渲染、输入、动作和安全服务；
- 脚本错误时保留上一份有效皮肤，界面不消失。

### 1.2 已接入范围

| 页面 | 实现方式 |
| --- | --- |
| Home | Lua Surface（`home`） |
| Player 控制层 / HUD | Lua Surface（`player`） |
| Merge 主界面 | Lua Surface（`merge`） |
| 字幕 | Lua Surface（`subtitle`，默认皮肤提供） |
| Toast 通知 | Lua Surface（`toast`，两个官方皮肤都提供；缺失时回退 C++ ImGui 版本） |
| 设置面板 | Lua Surface（`settings`，两个官方皮肤都提供；缺失时回退 C++ ImGui 版本） |
| Opening 过渡页 | C++ 原生绘制，消费 Lua token |
| Settings / Popup | C++ 原生弹窗，消费 Lua token |
| INFO / STATS 面板 | C++ 原生绘制，消费 Lua token |

`compatibility.surfaces` 在两个官方皮肤中都声明了 9 个名称（`home`、`opening`、`player`、`merge`、`hud`、`settings`、`popup`、`subtitle`、`toast`）。`home`、`opening`、`player`、`merge`、`subtitle`、`settings`、`toast` 都有可执行 `render` 函数；`hud`、`popup` 目前只提供 token。

**C++ 不再有任何 UI 兜底绘制。** 早期版本里没有 surface 时会回退到一套 C++ 界面，现在是「皮肤没实现该 surface，界面就不出现」。这条取舍是有意的：UI 的唯一来源是皮肤，回退界面会让「改皮肤」和「改功能」两件事纠缠在一起。

`player` surface 自带媒体信息与统计面板（由 `mediaInfo` / `statistics` 数据驱动，`p.showMediaInfo` / `p.showStats` 控制显隐），因此 C++ 的 `renderMediaInfo()` / `renderStats()` 只在不支持 player surface 的回退路径上生效。

设置弹窗打开时，底层 Lua Surface 保持可见但停止接收输入。

### 1.3 非目标

- v0.8.5 不实现自研 OpenGL UI 后端。当前是 **Lua-driven FluxUI + ImGuiBackend**：Lua 生成统一 Widget 树，FluxUI Core 负责布局、状态、事件白名单和资源校验，ImGuiBackend 负责绘制。复用现有窗口、字体、输入、焦点和弹窗能力。
- 不支持修改 C++ 核心逻辑（解码、同步、命令队列）。
- 不支持第三方网络加载皮肤。

FluxUI Core 与 Lua API 都不暴露 ImGui 概念：`ImDrawList`、`ImGuiWindowFlags`、`ImVec2` 不进入脚本层。未来若替换后端，是新增实现 `IFluxUIBackend`，而非改写 Lua 皮肤。

## 2. 架构设计

### 2.1 分层结构

```
┌─────────────────────────────────────────────────────────┐
│  Lua Skin Scripts                                        │
│  skins/<id>/<id>.lua — 静态 token + 可执行 Surface        │
└────────────────┬────────────────────────────────────────┘
                 │ ui.* / state.* / events.* / app.version
┌────────────────▼────────────────────────────────────────┐
│  FluxUI Core (C++)                                       │
│  ┌──────────────────────────────────────────────────┐   │
│  │ Widget 树 — Container / Text / Button / ...      │   │
│  │ 17 个构造器，解析自 Lua table                     │   │
│  └──────────────┬───────────────────────────────────┘   │
│  ┌──────────────▼───────────────────────────────────┐   │
│  │ 布局引擎 — VBox / HBox / Absolute                │   │
│  │ measure() → layout() → bounds                    │   │
│  └──────────────┬───────────────────────────────────┘   │
│  ┌──────────────▼───────────────────────────────────┐   │
│  │ 语义颜色解析 — color / theme → SkinSnapshot      │   │
│  └──────────────┬───────────────────────────────────┘   │
└─────────────────┼───────────────────────────────────────┘
                  │ DrawCommand / BackendEvent
┌─────────────────▼───────────────────────────────────────┐
│  Backend Adapter                                         │
│  ImGuiBackend：DrawCommand → ImDrawList / ImGui widget    │
│  Lua 不接触任何 backend API                               │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│  SkinManager                                             │
│  - 候选发现（User / Dev / BuiltIn）                       │
│  - LuaSkinLoader → 不可变 SkinSnapshot                    │
│  - LuaSkinRuntime → 沙箱 VM + Surface 执行                │
│  - 热重载监听（纳秒 mtime + debounce）                     │
└──────────────────────────────────────────────────────────┘
```

页面宿主 `HomeScreen` / `Controller` / `MergeScreen` 负责窗口循环与业务桥接，把数据推给 Lua、把白名单 action 收回来。

### 2.2 组件

`include/FluxPlayer/ui/FluxUI/FluxUI.h` 定义了后端无关的组件层：

```cpp
enum class LayoutMode { VBox, HBox, Absolute };

class IFluxUIBackend {
public:
    virtual ~IFluxUIBackend() = default;
    virtual void beginSurface(const std::string& name, const Rect& bounds) = 0;
    virtual void submit(const DrawCommand& command) = 0;
    virtual InputSnapshot input() const = 0;
    virtual std::vector<BackendEvent> takeEvents() = 0;
    virtual void endSurface() = 0;
};

/** Base node in a backend-neutral retained UI tree. */
class Widget {
public:
    virtual ~Widget() = default;
    Style style;
    std::string id;

    virtual Size measure() const = 0;
    virtual void layout(const Rect& bounds);
    virtual void emit(IFluxUIBackend& backend, const SkinSnapshot& skin) const = 0;
    virtual bool activateAt(Vec2 point, std::string& action,
                            std::unordered_map<std::string, std::string>& payload) const;
    const Rect& bounds() const { return bounds_; }
protected:
    Rect bounds_;
};
```

组件全部为 `final` 具体类：`Container`、`Text`、`Button`、`Spacer`、`RectWidget`、`LineWidget`、`GradientLine`、`Panel`、`GradientPanel`、`Input`、`Slider`、`Checkbox`、`CircleDashed`、`GearIcon`、`Image`、`RectGradient`、`RadialGradient`，以及为设置面板补齐的 `Scroll`、`Combo`、`NumberInput`、`SelectableList`。

`DrawCommand` 是唯一的绘制出口，包含几何、颜色、字体角色、切角、渐变和交互字段。`BackendEvent` 把输入控件的变更回抛给 Lua（`InputChanged` / `SliderChanged` / `CheckboxChanged` / `ComboChanged` / `NumberChanged`），后两者统一以 `widgetChanged` 动作回传，`ComboChanged` 额外带 `index`。

**滚动区的职责划分**：`Scroll` 只声明视口（后端压入裁剪矩形），**偏移量由皮肤自己持有**——皮肤知道自己的内容高，后端不该猜。皮肤每帧读 `ui.getInput().wheel`，累加后夹在 `[0, contentHeight - viewportHeight]`，把子控件坐标减去偏移再提交。这样绘制与命中天然一致，后端不需要做坐标换算。

### 2.3 布局

三种模式：

- **VBox**：垂直堆叠，自上而下，受 `gap` 和 `padding` 控制。主轴剩余空间均分给没有显式尺寸的弹性子元素；
- **HBox**：水平排列，自左而右，弹性分配同理；
- **Absolute**：容器设 `layout = "absolute"`，子元素设 `absolute = true` 并用 `x` / `y` 指定相对容器的偏移，用于播放器底栏这类需要精确坐标的界面。两个条件缺一不可——只设 `x` / `y` 而不设 `absolute = true` 不会生效。

`Align` 提供 `Start` / `Center` / `End` / `Stretch`，默认 `Stretch`。布局完全由 Lua 决定，C++ 不写 Player 专用视觉布局。

### 2.4 语义颜色解析

`color` 和 `theme` 都进入同一个角色解析器，可以是角色名，也可以是字面量：

```lua
color = "accentPrimary"     -- 角色名
color = "textMuted"
color = "#00E8FF"           -- 字面量
color = "#00E8FF80"         -- 含 alpha
```

可用的角色名（节选）：

| 分组 | 角色 |
| --- | --- |
| 背景 | `bgVoid`、`bgCanvas`、`bgPanel`、`bgPanelRaised`、`bgPanelTransparent`、`bgField`、`bgLocalButton`、`bgMergeButton`、`bgRadialCenter`、`bgRadialMiddle`、`bgRadialOuter` |
| 强调 | `primary` / `accentPrimary`、`accentPrimarySoft`、`accentPrimaryDim`、`secondary` / `accentSecondary`、`accentTertiary` |
| 文本 | `textPrimary`、`textSecondary`、`muted` / `textMuted`、`textDisabled`、`textSection`、`textFieldHint`、`textFooter`、`textSeparator` 等 |
| 状态 | `danger` / `stateError`、`success` / `stateSuccess`、`warning` / `stateWarning` |
| 结构线 | `linePrimary`、`lineSecondary`、`lineSubtle`、`borderVioletDim` |

字面量解析失败时回退到角色名分支。角色名未匹配时使用默认背景色。

`theme` 与 `color` 的区别在组件内部：`Button` 用 `theme` 决定描边色，用 `background` 决定填充色，两者共用同一解析器。

装饰（切角、辉光、扫描线）由 `decoration` 开关控制，具体绘制由 backend 决定。

### 3.1 组件构造器

所有构造器共享的通用字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 控件标识，输入控件用它匹配 `widgetChanged` 事件 |
| `width` / `height` | 固定尺寸；省略表示自适应 |
| `align` | `start` / `center` / `end` / `stretch`（默认 `stretch`） |
| `theme` / `color` | 语义颜色名 |
| `opacity` | 0～1，超出会被 clamp |

| `x` / `y` / `absolute` | Absolute 布局下的定位 |

`ui.text` 的 `baseline` 是相对文本框顶部的逻辑像素偏移，由后端按字体 ascent 定位；省略时保持垂直居中。

### 3.2 字体角色

`font` 字段取值为 `display` / `body` / `mono`：

- `display`：装饰性标题字体；
- `body`：默认正文字体；
- `mono`：独立等宽角色。启动时优先查找可执行文件旁 `fonts/consola.ttf` 及系统 Consolas；缺失时回退系统等宽字体（macOS 优先 Courier New，再 Menlo），最后使用 ImGui 内置等宽字体，并记录实际路径。

中文文件名 / 作者名会合并系统 CJK 字形。字体文件变更需要重启；Lua 对字体角色、字号和基线的调整支持热重载。

### 3.3 运行时服务

```lua
local width, height = ui.getWindowSize()   -- 窗口逻辑尺寸
local seconds = ui.getTime()               -- 皮肤启动以来的秒数
local path = ui.getAssetPath("logo.png")   -- 皮肤目录内资源，越界/不存在返回 nil
local skin = ui.getSkin()                  -- 有限颜色与字号
local rows = ui.getData("player")          -- 只读行数据
local input = ui.getInput()                -- { x, y, down, clicked, wheel }

state.set("key", "value")
local value = state.get("key")
events.emit("openLocalFile")
local version = app.version                -- 编译期写入的版本字符串
```

`ui.getSkin()` 只暴露有限字段——超出部分应由皮肤使用自己的 token：

```lua
skin.colors.accentPrimary     -- {r, g, b, a}
skin.colors.accentSecondary
skin.colors.textPrimary
skin.colors.textMuted
skin.typography.titlePx
skin.typography.bodyPx
```

`ui.getAssetPath()` 对候选路径做 canonical 校验，必须落在当前皮肤目录内且为常规文件，否则返回 `nil`。

`ui.getData(name)` 返回行数组，每行是字符串键值表。当前注册的数据提供器：

| 提供器 | 归属 | 内容 |
| --- | --- | --- |
| `player` | Controller | 播放状态、进度、音量、倍速、录制与下载状态 |
| `merge` | MergeScreen | 合并阶段、进度、输出选项 |
| `mergeClips` | MergeScreen | 片段列表 |
| `history` | HomeScreen | 观看历史 |
| `hardware` | HomeScreen | 硬件信息与能力检测结果 |
| `mediaInfo` | Controller | 文件名、网页视频信息、视频/音频参数（含 GOP）|
| `statistics` | Controller | 帧率、码率、丢帧、队列深度、硬解链路、`state` |
| `qualities` | Controller | 可下载画质列表 |
| `subtitle` | Controller | 当前字幕文本与控件可见性 |
| `toasts` | Controller | 当前活动通知：`type` / `icon` / `title` / `content` / `detail` / `alpha` / `slide` |
| `settings` | Controller | 全部设置项（由 C++ 注册表下发，见 §3.7）：`key` / `label` / `type` / `group` / `value` / `min` / `max` / `restart` / `hint` |
| `skins` | Controller | 皮肤候选：`id` / `label` / `valid` / `selected` / `index` |
| `opening` | OpeningScreen | 开场 splash：`mediaPath` / `phase` / `elapsed`（秒，用于驱动动画）/ `needsExtract` |

### 3.4 事件与 action 白名单

Lua 不注册 C++ 回调，只能 `events.emit(action, payload)` 投递白名单 action；未知 action 记日志并忽略。输入控件的变化由 C++ 作为 `widgetChanged` 事件回抛。

**Home**：`openLocalFile`、`openSettings`、`openMerge`、`playUrl`、`replayHistory`、`clearHistory`、`removeHistory`

**Player**：`togglePlayback`、`stop`、`seek`、`setVolume`、`toggleMute`、`download`、`toggleDownloadPause`、`cancelDownload`、`toggleVideoRecording`、`toggleAudioRecording`、`toggleMediaInfo`、`toggleStats`、`setQuality`、`setSpeed`、`cycleSpeed`、`openSettings`、`closeSettings`、`configChanged`、`widgetChanged`

**Merge**：`widgetChanged`、`mergeOption`、`mergeReset`、`mergeDuplicate`、`mergeMove`、`mergeAddFiles`、`mergeBack`、`mergeStart`、`mergeCancel`、`mergeClear`、`mergeSelect`、`mergeRemove`、`mergeAgain`

Merge 的编辑类 action（`widgetChanged`、`mergeOption`、`mergeReset`、`mergeDuplicate`、`mergeMove`）仅在 `Editing` 阶段生效；`mergeStart` 等按当前阶段校验。片段索引 payload 为从 1 开始的字符串，范围与阶段由宿主校验。

### 3.5 Player：进度与倍速

- `ui.getData("player")` 首行含 `current` / `duration`（秒）、`progress`（0～1）、`speed` 和 `maxSpeed` 等字符串字段，计算前用 `tonumber`。
- 进度滑块传入 0～1 的归一化进度，Seek 按 100ms 合并派发并保留最后一次拖动值；直接 `seek` action 仍以秒为单位。
- `maxSpeed` 每帧由宿主根据硬件能力与当前视频分辨率提供；首页与直接打开文件的播放器入口都会启动同一后台能力检测（不会重复启动），测速期间用硬件估算，完成后自动采用实测结果。
- Lua 从候选档位中筛选 `speed <= maxSpeed`，展开菜单每帧重新计算内容和高度。
- `setSpeed` 使用 `{ value = "2" }`；`cycleSpeed` 切换候选档位。两者都在宿主侧再次校验最新上限，不能绕过限制。
- `maxSpeed` 缺失时默认皮肤采用 1x 保守回退，不把 4x 或 16x 当作硬件能力。

### 3.6 Merge：数据与动作

- 默认皮肤使用 `ui.getData("merge")` 和 `ui.getData("mergeClips")` 获取状态和片段。
- IN / OUT 滑块使用 `mergeIn` / `mergeOut` 控件 id。
- 预览解码和纹理生命周期由 C++ 管理，Lua 只负责预览区域与双栏布局。
- 默认皮肤支持每页 3 个片段、页内拖拽排序、预览、重置、复制片段和输出分辨率 / GOP 设置。

### 3.7 Settings：设置项协议

设置面板已经由皮肤接管，C++ 只保留「注册表 + 落地」。这条协议是**唯一新增功能不用改 C++ 绘制代码**的关键：

- 皮肤用 `ui.getData("settings")` 拿到全部设置项（含 `type` / `group` / `min` / `max` / `hint`），
  按 `type` 分派到 `ui.checkbox`（`bool`）、`ui.numberInput`（`int`）、`ui.input`（`number` / `text`）；
- 用户改动后统一发 `configChanged { key = <设置项 key>, value = <字符串> }`，不发送分组或控件 id；
- **类型校验、范围夹取、白名单、持久化都在 C++ 的注册表里**（`src/ui/SettingsSchema.cpp`）。
  非法值被拒绝，皮肤下帧重读 `settings` 即自然回弹，不需要本地维护一份镜像状态；
- 注册表中 `write` 返回 `false` 表示落地失败（例如皮肤切换失败），此时保留原值；
- `requiresRestart` 为真的项，皮肤负责显示提示（如 TCP 日志端口）；
- 少数设置同时是运行时状态：`loopPlayback`、`subtitleEnabled`、`skinId`、`logLevel`、
  `logFileEnabled` 在落盘之外还会立即作用到当前会话，这套副作用收在注册表的 `write` 里。

### 3.8 Opening：开场 splash

`OpeningScreen` 在 `Player::open` 返回前显示过渡界面。它**早于 Controller 存在**，
因此自己持有一个 `ImGuiBackend`，并在 splash 期间临时挂上 `opening` 数据供给
（Controller 起来后会接管 provider）。`elapsed` 由宿主按 `ImGui::GetTime()` 起点算出，
皮肤用它驱动呼吸点动画——不要用 `ui.getTime()`，那个基准是皮肤启动时刻，与本次打开不对齐（尤其热重载后）。

### 3.9 播放器弹层

倍速菜单、画质列表、亮度竖条、下载进度与详情、录制计时器全部在 `player` surface 内绘制：

- 菜单的展开状态存在 `state.set("speedMenu" / "qualityMenu" / "brightnessPopup")`；
- 倍速候选按 `maxSpeed` 每帧重算，画质列表来自 `qualities` 提供器；
- 下载面板的落位/阶段文案（`LIVE SAVE` / `PROBING` / `N% · VOD`）与中转链路
  （`D:`/`E:`/`ZC:`）都在皮肤里，C++ 只给数值；
- 录制计时器的秒数与字节数由 `recordingVideoTime` / `recordingVideoSize` 等字段提供，
  排版（`V 01:23 4.5MB`）由皮肤决定。

新增一个设置项只需在 `SettingsSchema.cpp` 的表里加一行——两个官方皮肤都会自动多出一行控件。

## 4. 皮肤脚本结构

### 4.1 入口

```text
skins/<id>/<id>.lua
```

目录名、Lua 文件名和脚本返回表的 `id` 三者必须一致。默认皮肤：

```text
source/UI/skins/cyberpunk-neon/cyberpunk-neon.lua
```

`skin.json` 不再参与扫描、加载、打包或热重载。`minimal-lua/minimal-lua.lua` 是第二套完整的单文件示例皮肤。

### 4.2 包结构

```text
skins/<id>/
  <id>.lua            # 唯一入口：静态 token + 可执行 Surface
  preview.svg         # 包内预览
  mockup_*.svg        # 设计稿，默认皮肤保留
  logo.png
  fonts/              # 可选
  textures/           # 可选
```

### 4.3 单文件结构

脚本返回一个表，静态 token 与可执行 Surface 写在同一文件：

```lua
local skin = {
    schemaVersion = 1,
    id = "my-skin",
    name = "My Skin",
    version = "1.0.0",

    compatibility = {
        skinApi = 1,
        -- 声明皮肤为这些界面提供 token；带 render 的才是可执行 Surface
        surfaces = { "home", "opening", "player", "merge", "settings", "subtitle", "toast" },
    },

    roles = { ... },       -- 语义颜色
    gradients = { ... },   -- 渐变定义
    metrics = { ... },     -- 圆角、间距、尺寸、透明度
    -- surfaces 表是纯皮肤私有数据：既可以挂 render 函数，也可以放几何 token，
    -- 两者同处一表，C++ 不解析、不校验、也不读取其中任何数值。
    surfaces = {
        home = { render = render_home, cardPaddingX = 32 },
        player = { render = render_player },
        merge = { render = render_merge },
        settings = { maxWidth = 920 },
    },
    motion = { ... },      -- 自动隐藏、脉冲、重载防抖
    typography = { ... },  -- 字体族与字号
    decoration = { ... },  -- 切角、辉光、扫描线开关
    assets = { preview = "preview.svg" },
}

skin.surfaces.home.render = function()
    local width, height = ui.getWindowSize()
    return ui.container {
        layout = "vbox",
        align = "center",
        gap = 12,
        ui.text { content = "MY PLAYER", color = "textPrimary" },
        ui.button {
            text = "OPEN LOCAL FILE",
            action = "openLocalFile",
            width = math.min(360, width - 80),
            height = 48,
        },
    }
end

return skin
```

**静态 token 分类**：

- `roles`：背景、强调色、文本、状态色和结构线；
- `gradients`：进度轨、Dock 边缘和面板标题；
- `metrics`：圆角、间距、尺寸和透明度（**唯一被 C++ 读取的几何来源**）；
- `motion`：自动隐藏、脉冲和重载防抖（含 `reloadDebounceMs`）；
- `typography`：字体族与字号；
- `decoration`：切角、辉光、扫描线等开关；
- `assets`：包内预览、字体和纹理。

`LuaSkinLoader` 只读取 `roles` / `gradients` / `metrics` / `motion` / `typography` / `decoration` / `assets` 生成不可变 `SkinSnapshot`——这些是 C++ 应用 ImGui 全局样式与绘制装饰所需的公共样式。

**`surfaces` 不在快照里**：界面尺寸是皮肤业务，`skin.surfaces.<name>.<字段>` 由皮肤脚本自己直接读取（同一个 table 就在脚本顶部），C++ 既不解析也不校验。这与「UI 的唯一来源是皮肤」一致：渲染引擎需要的一切几何都在每帧的 draw 命令里传进来，不需要预先统计。

**可执行 Surface**：`surfaces.<name>.render` 是一个无参函数，返回 Widget 树。`LuaSkinRuntime` 在沙箱 VM 中执行它，生成 backend-neutral FluxUI 树。

完整字段示例见：

- `source/UI/skins/cyberpunk-neon/cyberpunk-neon.lua`（1279 行）
- `source/UI/skins/minimal-lua/minimal-lua.lua`（578 行）

### 4.4 单文件约束

每个皮肤只能有一个脚本入口 `<id>.lua`。Home、Player、Merge 等可执行 Surface 都在这个文件内定义为 `surfaces.<name>.render`；预览图、字体和纹理可以作为非 Lua 资源随包分发。旧式 `skin.json`、`skin.lua` 和 `layouts/*.lua` 不再加载，也不再随内置皮肤发布。

## 5. C++ 服务边界

### 5.1 模块职责

| 模块 | 职责 |
| --- | --- |
| `SkinManager` | 候选发现、优先级、热重载监听、原子快照交换 |
| `LuaSkinLoader` | 从 `<id>.lua` 读字段、范围校验、资源校验，生成 `SkinSnapshot` |
| `LuaSkinRuntime` | 沙箱 VM、配额、Surface 执行、事件分发、数据注入 |
| `FluxUI` | Widget 树、布局、命中测试、DrawCommand |
| `ImGuiBackend` | DrawCommand → ImDrawList / ImGui widget |

`LuaSkinRuntime` 的公开接口不含任何 Lua 或 ImGui 类型：

```cpp
class LuaSkinRuntime {
public:
    using Payload = std::unordered_map<std::string, std::string>;
    using ActionHandler = std::function<void(const std::string&, const Payload&)>;
    using DataProvider = std::function<std::vector<Payload>(const std::string&)>;

    bool initialize(const std::string& skinDirectory,
                    std::shared_ptr<const SkinSnapshot> skin,
                    const std::string& entryFile);
    void shutdown();

    /** 重载脚本；失败时旧 VM 继续生效。 */
    bool reload();

    bool hasSurface(const std::string& surfaceName) const;

    /** 构建、布局并提交一个 Surface；返回 false 请求 C++ 回退。 */
    bool renderSurface(const std::string& surfaceName,
                       FluxUI::IFluxUIBackend& backend,
                       const FluxUI::Rect& bounds,
                       float deltaTime = 0.0f);

    void setSkin(std::shared_ptr<const SkinSnapshot> skin);
    void setActionHandler(ActionHandler handler);
    void setDataProvider(DataProvider provider);

    std::string lastError() const;
    size_t memoryUsed() const;
};
```

线程约定：`SkinManager::initialize` 必须在主线程、ImGui 上下文创建之前调用一次；`selectSkin` / `reloadActive` / `setHotReloadEnabled` / `shutdown` 必须在 UI 线程调用。

### 5.2 Lua 不提供的能力

- 皮肤配色和具体几何决策由 Lua 拥有，C++ 不隐式覆盖；
- Lua 不能任意访问播放器内部对象（不给 `Player*`、`HomeScreen*`、`Controller*`）；
- 无原生模块、FFI、文件或网络能力。

仅当所有默认 Lua 副本都损坏时，编译期紧急快照保证程序仍能启动。

## 6. 热加载事务

启用 Settings > Appearance > Hot Reload 后，`SkinManager` 监听当前 `<id>.lua`。

```text
纳秒 mtime 变化
  -> 防抖（默认 160ms，可由 motion.reloadDebounceMs 覆盖）
  -> 独立 VM 中读取 + 解析 + 校验新 Lua
  -> 成功：generation + 1，原子交换 VM 与 SkinSnapshot
  -> 失败：保留旧 VM 与快照，记录 traceback
```

实现要点：

1. 后台线程只做 `stat` + 防抖 + 触发，真正的快照替换在 UI 线程完成；
2. 重载时先构建**替换 VM**，只有 `create()` 成功才释放旧 VM 并转移状态，因此失败的编辑不会中断当前界面；
3. VM 转移后重新指向 `FluxPlayer.runtime`，Lua 侧缓存的闭包仍然有效；
4. mtime 使用纳秒级 tick，支持同一秒内多次保存；
5. 只监听当前 `<id>.lua` 及其已解析的预览、字体和背景资源。

UI 每帧比较 generation：

- Home 更新 FluxUI Surface 和样式；
- Opening 更新面板参数；
- Controller 更新 Dock、HUD、Settings、Popup 和 Subtitle；
- 清屏色和装饰在后续帧同步变化。

脚本错误时在 Appearance 状态栏显示，并可点击 `RELOAD NOW` 手动重载。因此可以在播放器运行期间直接调整颜色、尺寸、间距、动画参数和 Lua Surface，无需重启，也不重置播放状态。

## 7. 搜索与回退

优先级：

| 来源 | 路径 | 优先级 |
| --- | --- | --- |
| User | `<AppData>/skins/<id>/<id>.lua` | 最高 |
| Dev | `<cwd>/source/UI/skins/<id>/<id>.lua` | 中 |

## 8. 资源校验

`assets` 与 `ui.getAssetPath()` 的路径必须相对皮肤目录，canonical 后仍位于该目录内。

允许的扩展名：

- `.ttf`、`.ttc`、`.otf`
- `.png`、`.svg`

单资源不超过 **4 MB**，整个皮肤目录不超过 **16 MB**。设计稿 SVG 可以保留，但只有 Lua 中显式引用的资源参与运行时。

`ui.getAssetPath()` 对越界路径、非普通文件和缺失文件一律返回 `nil`，不抛错。

## 9. 安全与限制

### 9.1 沙箱

沙箱以**只打开需要的库**方式建立，而不是先全部打开再置空，避免 `package.loaded` 中残留危险模块：

```cpp
void sandbox() {
    // 只保留纯计算所需库
    luaL_requiref(state, LUA_GNAME,        luaopen_base,       1); lua_pop(state, 1);
    luaL_requiref(state, LUA_TABLIBNAME,   luaopen_table,      1); lua_pop(state, 1);
    luaL_requiref(state, LUA_STRLIBNAME,   luaopen_string,     1); lua_pop(state, 1);
    luaL_requiref(state, LUA_MATHLIBNAME,  luaopen_math,       1); lua_pop(state, 1);
    luaL_requiref(state, LUA_UTF8LIBNAME,  luaopen_utf8,       1); lua_pop(state, 1);
    luaL_requiref(state, LUA_COLIBNAME,    luaopen_coroutine,  1); lua_pop(state, 1);

    const char* blocked[] = {"io", "os", "debug", "package", "require", "dofile",
                             "loadfile", "load", "ffi", "collectgarbage"};
    for (const char* name : blocked) { lua_pushnil(state); lua_setglobal(state, name); }
}
```

内存配额在创建 `lua_State` 时即通过自定义 allocator 生效，而不是初始化后再补：

```cpp
state = lua_newstate(quotaAllocator, quota.get());
```

指令预算通过 `lua_sethook(LUA_MASKCOUNT)` 实现，每次执行前重置为 10 万条，超出即 `luaL_error` 中断。

### 9.2 限制汇总

| 限制项 | 值 |
| --- | --- |
| 单脚本大小 | 256 KB |
| VM 内存上限 | 16 MB |
| 单次执行指令数 | 100,000 |
| Widget 深度 | 32 层 |
| 单容器子节点 | 1000 |
| 单资源大小 | 4 MB |
| 皮肤目录大小 | 16 MB |
| 开放标准库 | `base`、`table`、`string`、`math`、`utf8`、`coroutine` |
| 禁用 | `io`、`os`、`debug`、`package`、`require`、`dofile`、`loadfile`、`load`、`ffi`、`collectgarbage` |

### 9.3 错误处理

Lua 调用统一使用 `luaL_loadbuffer` + `lua_pcall` 包装，失败时用 `luaL_traceback` 取完整调用栈写入 `lastError()`。错误时保留上一个可用 Widget 树；没有可用树才回退到 C++ 原生 UI。因此热重载期间写坏脚本不会让整个界面消失。

## 10. 构建与安装

### 10.1 Lua 运行时

固定使用仓库内置 Lua **5.4.8**（`third_party/lua/`），保证三端版本一致，发布包不依赖系统安装。CMake 侧编译为独立静态库：

```cmake
file(GLOB LUA_SOURCES CONFIGURE_DEPENDS "third_party/lua/src/*.c")
add_library(lua_static STATIC ${LUA_SOURCES})
target_include_directories(lua_static PUBLIC third_party/lua/src)
target_compile_definitions(lua_static PRIVATE
    $<$<PLATFORM_ID:Windows>:LUA_USE_WINDOWS>
    $<$<PLATFORM_ID:Darwin>:LUA_USE_MACOSX>
    $<$<PLATFORM_ID:Linux>:LUA_USE_LINUX>
)
```

不使用 LuaJIT：JIT 后指令 hook 对死循环的中断不如解释器路径可预期，`ffi` 也会直接打穿沙箱。

### 10.2 资源复制

CMake、xmake、CMake install 和 macOS 打包脚本都会复制整个皮肤目录到 `resources/skins/<id>`。

复制有两个刻意的设计：

- **不是 POST_BUILD**：POST_BUILD 随可执行文件重新链接而触发，而 Lua/SVG 皮肤不参与编译。这里用 stamp 文件显式声明 `DEPENDS`，皮肤内容变化即重新复制。曾因此出现「改了皮肤、`cmake --build` 报 Built target、但运行目录仍是旧皮肤」。
- **先删目标再拷贝**：`copy_directory` 只做覆盖，不会清除已删除的旧皮肤或历史嵌套目录（`source/source/...`、`skins/skins/...`），残留旧文件会被运行时误加载。

发布产物中不含 `skin.json`。

## 11. 验收标准

- `<id>/<id>.lua` 存在，目录名、文件名、返回表 `id` 三处完全一致；
- 设置页只把 `<id>.lua` 识别为候选；皮肤包不含旧式 `skin.lua` / `layouts/`；
- 两个单文件皮肤（`cyberpunk-neon`、`minimal-lua`）可双向切换；
- Home 必要动作可达；Opening、Player、HUD、Settings、Popup、Subtitle 参数合法；
- 修改激活 Lua 后能热加载，generation 增加；
- Lua 语法或范围错误时保留上一有效皮肤，界面不消失；
- 打包目录中没有 `skin.json`，Lua `assets.preview` 指向现存资源；需要保留的 `mockup_*.svg` 未丢失；
- Lua 沙箱、内存与指令预算、路径逃逸测试通过。

## 12. 风险与后续

### 12.1 已缓解的风险

| 风险 | 缓解 |
| --- | --- |
| 脚本安全性 | 只开 6 个纯计算库，禁用 `io`/`os`/`debug`/`package`/`require`/`load*`/`dofile`/`ffi`；内存与指令配额；资源路径 canonical 校验与大小限制 |
| 写坏脚本导致界面消失 | 独立 VM 构建成功才原子交换；失败保留上一有效 VM |
| 后端过渡变成永久绑定 | Lua API 只暴露 FluxUI 抽象类型；示例脚本禁止出现 ImGui 类型；新增后端只需实现 `IFluxUIBackend` |
| 改了皮肤但不生效 | 资源复制改用 stamp 依赖 + 先删后拷，避免 POST_BUILD 与残留文件问题 |
| 单文件迁移 | 候选扫描与运行时只接受 `<id>.lua`，内置皮肤不携带旧脚本 |

### 12.2 尚未实现（规划）

以下条目在本文档的早期版本中曾被描述为已完成，实际尚未落地，列出以明确边界：

- **Flexbox 布局**：当前只有 `VBox` / `HBox` / `Absolute`，无 flex-grow / flex-shrink / justify-content。
- **声明式动画系统**：无 `ui.animated` 及缓动函数 API。皮肤目前通过 `ui.getTime()` 在 Lua 内自行计算动画。
- **`ui.invalidate()`**：不存在该接口。Widget 树每帧重建，布局由 `measure()` / `layout()` 完成，没有显式失效机制。
- **粒子效果与自定义组件 `require`**：不可用，`require` 已被禁用。
- **OpenGLBackend**：未开始。字体 atlas、文本排版、裁剪、批处理、IME、焦点与鼠标命中均需补齐。
- **性能指标**：未建立自动化的每帧开销基准测试。

## 13. 总结

v0.8.5 的皮肤系统把 UI 全部交给脚本层，C++ 退化为渲染引擎与落地层：

1. **单一来源**：C++ 不绘制任何界面，也不保留兜底外观。皮肤没实现某 surface，该界面就不出现；
2. **单文件模型**：一个 `<id>.lua` 同时提供静态 token 与可执行 Surface；
3. **实时反馈**：修改保存后秒级生效，不重启、不重置播放；
4. **逻辑表达**：支持条件渲染、响应式计算和基于 `ui.getTime()` 的自定义动画；
5. **统一边界**：Lua 拥有皮肤业务，C++ 只提供沙箱、绘制、输入、动作与安全服务；
6. **可替换后端**：Lua API 与 ImGui 解耦，未来可新增现代渲染后端而不改皮肤。

**下一步**：`hud` 与 `popup` 两个 surface 目前只有 token、没有 render；Flexbox 与声明式动画 API 仍待补齐；Phase 4 的 OpenGLBackend 需要文本排版与输入法方案，并建立自动化性能基准。
