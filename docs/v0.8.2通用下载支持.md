# FluxPlayer 网络下载与直播保存

## 1. 入口与任务归属

Player 保存原始网络来源 URL，Controller 对网络来源显示 Download，本地文件不显示该入口。Downloader 使用独立工作线程和 FFmpeg 输入/输出上下文，不复用正在播放的解码器，也不依赖 ffmpeg 命令行工具。

`Downloader::start(sourceUrl, outputDir, formatId, onProgress, onFinish)` 启动任务。进度和完成回调在工作线程触发，UI 复制快照后显示。暂停、恢复和取消通过原子标志传递，取消同时供输入中断回调读取；析构调用 cancel 回收任务。

## 2. 来源解析与模式判断

`extractStream()` 通过 `StreamExtractor::needsExtraction()` 判断输入：已识别的媒体直链直接交给 FFmpeg，网页来源通过 yt-dlp 提取。原始来源 URL 保留给重试使用，避免把带时效签名的提取地址当作长期来源。

网页提取结果包含直播标记和 duration。打开输入后，如果没有明确直播标记且 duration 不可用，用 FFmpeg 容器 duration 补齐。当前分类规则为：

- `isLive` 为真：`LiveSave`。
- 否则 duration 大于零：`VodDownload`。
- 其余：`LiveSave`。

这是直播标记与时长启发式分类，不包含 HLS/DASH manifest 的静态/动态精确判断，也不进行 RTSP/RTMP 快拉采样。无扩展名 HTTP 来源仍受 `needsExtraction()` 的分类规则影响。

## 3. 媒体处理

当前执行 `PacketRemux`：读入压缩包，映射音视频流和时间戳后写入输出容器，不解码、不编码。DASH 分离视频和音频分别打开，再合并写入。UI 的 decoder/encoder 为 `BYPASS`，zero-copy 为 `N/A`；枚举中的 HardwareTranscode/SoftwareTranscode 不表示下载执行了转码。

写入循环不按播放器时钟节流，实际速度受网络、服务端和存储限制。输出容器在打开前按提取信息选择：DASH、直播或未知时长使用 MKV，其余使用 MP4。容器不兼容时报告错误，不自动建立硬件或软件转码管线。

## 4. 文件与停止语义

下载写入 `最终文件名.part`。标题经过文件名清理，文件名冲突时追加序号；最终提交使用不覆盖语义，Windows 使用不带替换标志的 MoveFileExW，POSIX 使用 link/unlink。

- VOD Cancel：中断任务并删除临时文件。
- Live Stop：中断读取，执行封口流程，提交已保存内容。
- 正常 EOF：执行封口并提交最终文件。
- 提交失败：返回错误，不覆盖已有最终文件。

Windows 文件路径通过 UTF-8 到 UTF-16 转换调用宽字符文件 API。

## 5. 暂停、重连和进度

写入循环检查暂停与取消。网络失败采用指数退避重连，最大等待间隔为 30 秒；重新提取和打开来源后按已有媒体时间尝试恢复。该行为是按时间戳恢复，不是字节级断点续传；直播暂停不能补回服务端未保留的内容。

`DownloadProgress` 包含模式、任务状态、管线、百分比、速度、ETA、文件大小和保存时长。状态包括 Probing、Downloading、LiveSaving、Paused、Reconnecting、Finalizing。VOD 使用百分比语义，Live 显示保存时长；未知文件大小可由时长和码率估算。

## 6. 实现边界

- 单任务运行，不提供下载队列、定时录制或保存时实时预览。
- 下载管线仅转封装，不提供分辨率、码率或编码器选择。
- 不提供跨设备同步或 DRM 绕过功能。
- 网络中断依赖 FFmpeg 协议配合，不保证取消瞬时返回。
- 播放器亮度属于显示 shader 参数，不改变下载文件。
